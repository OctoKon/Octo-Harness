02 · Architecture

Three layers. One agent loop.

A Tauri 2 shell in Rust, a Svelte 5 interface, and a Node engine built on Pi. The window never talks to your provider directly; every request goes through the engine and its policy.

  1. Svelte UI shows the conversation and approvals
  2. Typed bridge into the Rust shell
  3. Pi-based engine runs the agent loop
  4. Tools act inside your workspace
  5. Requests go to the provider you chose

03 · A chat turn, end to end

From prompt to proof.

Each turn follows the same path, and each step leaves something you can inspect afterwards.

  1. You describe the task
  2. Policy is checked before dispatch
  3. The model streams a reply or asks for a tool
  4. Risky tools wait for your approval
  5. Results come back as tool cards
  6. The answer lands with its evidence

04 · Safety by default

Nothing happens behind your back.

Safety is the default path, not a setting you have to find.

  1. Secrets are redacted before anything is shown or saved
  2. Tools are confined to the chosen workspace
  3. Commands and writes ask for approval
  4. When something is uncertain, it fails closed

05 · Memory and code search

Context it can find, and you can see.

Memory is optional and built from committed evidence, not every chat token. Code indexing is a separate path.

  1. Evidence is committed by the engine
  2. Memory is derived into a per-project store
  3. Code indexing runs as a separate path
  4. Answers point back to their sources

06 · Helper agents

Split the work. Keep it apart.

Write helpers work in their own Git worktrees; only a reviewed patch reaches your workspace. The engine module exists; desktop session wiring is still in progress.

  1. The main agent hands off a bounded task
  2. Read helpers share the project
  3. Write helpers get their own Git worktree
  4. Only a reviewed patch comes back

07 · Bring your own provider

Your endpoint. Your key. Your model.

Any OpenAI-compatible endpoint works. Today's demo runs on Pollinations. Splyce never switches providers or models on its own, and never guesses token limits for a custom model.

The API key is stored in Windows Credential Manager and the field is cleared after saving.
