# Combined Codex and Claude UX: 2026-10 refresh

**Status: research disposition, 2026-10-26; runtime and usability evidence n=0.** The leads' goal is the best coding-agent desktop UX, using Codex and Claude as the base and beating both by combining their strengths. This refresh re-read current official Codex and Claude documentation, checked notable Zed, Cursor and Kiro mechanisms, and mapped each user job against this dossier. Records: [R32 ledger](../evidence/r32-sweep-sources.json). No proprietary asset, code or trade dress is reused; Splyce adopts mechanisms, not appearance.

## Proposed advantages (unmeasured)

Splyce's native one-use approvals bound to digest, revision and expiry (FUI-W5), snapshot-bound `verified_complete` receipts, explicit fork ancestry, requested-versus-effective model per role, honest unknown usage, and a barebones base with inert module discovery are designed to be stronger than either product's documented behavior; whether users experience them as better is unmeasured until `O1_competitive_claim` and usability studies run. The gaps below are mechanisms both competitors ship that the dossier lacked.

| `U1_steer_queue`          | During a run, steer A and queue B and C; the UI lists them in order with IDs and classes, and deleting C leaves only A and B in the engine log. Cancel freezes queue consumption at the TD-14 handoff and records each message's disposition: only engine-confirmed undelivered messages return to the composer, once, in order with their IDs, while consumed ones show as delivered (A consumed before cancel returns only B; cancel before consumption returns A then B). ## Basis corrections

- The dossier's Codex basis cited the early-2026 macOS launch. Current [Codex documentation](https://learn.chatgpt.com/docs/features) lists a Windows desktop app, Windows sandbox, Auto-review, profiles and plan mode; a Windows-native competitor now exists and is the direct comparator. Reports that Codex folded into the ChatGPT desktop app are secondary and unverified.
- Codex review now has first-class [unstaged, staged, commit, branch and last-turn scopes with per-hunk actions](https://learn.chatgpt.com/docs/code-review); the dossier's scope list gains commit and last-turn.
- [Claude Code Desktop](https://code.claude.com/docs/en/desktop) now documents permission modes (manual, accept edits, plan, auto, bypass), a context card, fork at a message, a code-review card, side chats, pop-out panes and finish notifications. The dossier's single-workbench, no-docking decision stands; side chats and pop-outs remain deferred until user tests show need.
- Claude's [screen-reader mode](https://code.claude.com/docs/en/accessibility) is the strongest public competitor accessibility bar. It is opt-in and terminal-scoped; Splyce meets its semantics by default in the main UI.
- [Claude rewind](https://code.claude.com/docs/en/checkpointing) documents its own limits (shell, subagent and external changes are not restored). `C3_user_rewind` makes those limits explicit to the user instead of silent.

## Known day-one gaps

Codex and Claude desktop both ship integrated browser previews with rendered-state verification ([Codex browser](https://learn.chatgpt.com/docs/browser), [Claude desktop](https://code.claude.com/docs/en/desktop)); Splyce V1's base has no browser or preview, and that optional work follows R1. Augment's Pi-derived Auggie ships a codebase-retrieval engine; Splyce's base uses ordinary search. These gaps stay explicit in release notes and claims until qualified optional modules close them.
Limits: no installed competitor was audited; Codex steer/queue keys, plan display and context indicator lack primary pages and are not used as evidence.
