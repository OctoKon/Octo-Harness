# Codex and adjacent OpenAI product capabilities

**Snapshot: 2026-10-25.** Official documentation review; Splyce implementation and comparative results are **n=0**. Splyce keeps execution and stored state local; inference profiles can be local or explicitly authorized cloud APIs with no silent fallback. Hosted products below are behavioral comparators, never a required executor, memory backend, or fallback. Sources: [CP-01–CP-18](../evidence/codex-product-sources.json).

## Distinct layers

The open Codex CLI/harness, app-server protocol and SDKs are different from the desktop/IDE product experience and managed cloud services. A public client repository does not transfer rights to hosted models, account entitlements or proprietary UI. Current documentation also distinguishes new Codex Cloud environments from a legacy experience. Do not infer one surface's features, availability or limits from another.

## Follow-up chains that change the plan

**Embedding chain:** the platform overview advertises reusable harness components → SDK docs distinguish automation from a custom client protocol → app-server docs distinguish transport/field gates while retaining an experimental command/production-support warning → local-provider configuration establishes an offline-capable path. The [pinned engine assessment](../foundations/codex-engine-assessment.md) confirms the Apache-2.0 Rust source and specific provider boundaries. Consequently Codex is a legitimate existing-base comparator, especially for the earlier Rust preference, but the full combination still needs one identical F0/locality/footprint experiment. Do not mistake a well-documented protocol for an accepted integration.

**Product parity chain:** a shared plugin ecosystem does not mean identical support → the plugin page explicitly excludes IDE support → scheduling docs also distinguish CLI/IDE from desktop/web management. Splyce should define capability manifests per client and report unsupported features, then test consistent results through each advertised client. Copying every UI is not a condition of a reliable headless core.

**Efficiency chain:** parallel workers and persistent worktrees improve workflow opportunities → workers add model/tool tokens and worktrees add environment/cleanup costs → the existing [efficiency review](../capabilities/efficiency-and-recursive-improvement.md) requires full-lifecycle matched trials. An optional worker must earn its activation against the single-agent baseline.

The earlier blanket local-only restriction is superseded: authorized cloud-profile trials are opt-in, scoped and cost/credential safe. All-local profile comparisons stay local. Local OSS comparators can use identical local model/runtime/task inputs where their interfaces support them. Published service scores remain external context, not paired Splyce superiority evidence. Claims must specify task, model, hardware, authority, quality, cost and tested client; parity fixtures and the [qualification register](../design/qualification-register.md) control promotion.
