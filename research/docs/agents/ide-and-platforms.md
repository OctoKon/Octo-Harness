# IDE and agent-platform landscape

**Research date:** 2026-10-25. **Status:** documentation verified; none of these products was installed or tested. Claims below are bounded to the linked first-party documentation or source repositories.

## Chained research rounds

### 1. Discovery: identities and layers

The ecosystem separates into four overlapping layers: an editor/IDE surface, an agent harness (context, tools, approvals, trajectory), a sandbox/execution plane, and cloud task/PR orchestration. A future unified CLI should keep those seams explicit: it can be an agent-harness client without becoming an IDE, model vendor, or cloud-hosting vendor.

`Roo Code` and `Zoo Code` are separate identities. Roo's own preserved documentation says its extension was shut down on 2026-05-15 and points to ZooCode. Zoo identifies itself as a community-maintained Roo fork, with compatible settings and Apache-2.0 provenance. “roo/zoo” therefore cannot safely mean “Roo or Zed”: `Zed` is a separate editor and ACP client.

### 4. Architecture synthesis for a future unified CLI

Adopt a small local contract rather than copying any vendor UI:

1. **Run manifest**: task, workspace/ref, model/provider, instruction sources, declared tools, policy, time/cost limits and sandbox descriptor.
2. **Append-only event stream**: prompt, tool request, policy decision, action result, diff/checkpoint reference, test evidence, stop reason. This supports IDE views, headless CI, task boards and audit without divergent agent state.
3. **Execution provider interface**: local guarded process, container, remote VM or delegated provider; each reports its isolation capability instead of the CLI implying it.
4. **Review/apply boundary**: an execution produces a branch/worktree/diff and evidence bundle. Applying to a user workspace stays explicit unless policy permits otherwise.
5. **Capability negotiation**: adapters declare checkpoint, worktree, ACP, MCP, browser, artifact, resume, and approval capabilities. Do not silently emulate unavailable safety features.

### Feature conflicts to resolve up front

| Conflict                                                                                     | Required decision                                                                                          |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| “Approve every action” (Cline/Copilot default) vs unattended cloud execution (Cursor/Replit) | Policy must be run-scoped and auditable; no global hidden auto-approve.                                    |
| Checkpoint rollback vs Git history vs task apply                                             | Define each separately: checkpoint restores files, Git preserves history, apply merges an isolated result. |
| Host process convenience vs container/VM isolation                                           | Make the isolation level visible in every run result; reject an implicit downgrade.                        |
| Shared IDE ownership vs external-agent ownership (ACP)                                       | The client renders/reviews; the agent owns only declared runtime/config state.                             |
| Vendor-specific rules/profiles                                                               | Convert only an explicitly mapped subset; retain source provenance and warn on unsupported fields.         |

### Five acceptance tests for the future harness

1. A denied shell/network request produces an event with rule and capability context, makes no change, and is distinguishable from a tool failure.
2. Two simultaneous tasks editing the same repository execute in independent worktrees/sandboxes; neither can observe the other’s uncommitted files.
3. A run resumed after interruption reproduces its manifest and event cursor, then requires a new policy decision for any unapproved pending action.
4. A completed run yields a diff/branch plus exact test command, exit code and captured output reference; “complete” cannot be emitted without this evidence object.
5. An ACP/MCP/provider adapter that lacks checkpoint or sandbox support advertises that absence; the CLI never labels the run “isolated” or “restorable.”
