# Browser, computer and device access

**Active product scope:** Splyce keeps agent execution and stored state local. Each inference role may use a local runtime or an explicitly authorized cloud API profile with recorded endpoint, model/revision, and egress scope; it never silently switches provider or falls back. Hosted memory and executors below remain comparative research, not product dependencies. [Current master plan](../../../MASTER-PLAN.md).

**Status: proposed integration and qualification plan; runtime evidence n=0.** This note records public-source capabilities and proposed Splyce controls. It does not claim a working browser, desktop, mobile, connector, device, or approval flow. Pi owns the model loop and built-in MCP registration/discovery; Splyce owns grants, effect receipts, artifact retention, reconciliation and derived memory. Source records are [CA-01–CA-20](../evidence/computer-access-sources.json).

The starting reuse is **Playwright MCP core tools with accessibility snapshots in an isolated context**. This is a source-supported implementation direction because Playwright exposes structured accessibility snapshots and keeps higher-risk storage, vision, developer, PDF and network functions capability-gated. The claim that DOM/accessibility first is cheaper or more reliable for Splyce than vision is a **hypothesis**, to be tested against the same fixtures and budget. Vision is a fallback for controls absent or unusable in semantic trees, not a hidden general fallback.

## Browser and web controls

Playwright MCP is the first qualification target: its public documentation describes accessibility snapshots, browser operations, optional capability groups, browser selection, device emulation, storage state, tracing/video and existing-browser attachment. Attachments, storage, arbitrary evaluation, unrestricted file access, downloads, PDF, network interception, recordings and coordinate tools are separately classified because they enlarge authority or retention surface. A connector must pin an exact package version or source revision before adoption; `latest` examples are discovery material, not an adoption pin.

Chrome DevTools MCP is a separate Chrome-only inspection/debug candidate. Its documentation warns that an agent connected to an authenticated browser can read, inspect, modify and act through accessible browser data. It therefore requires a distinct profile and explicit resource grant. WebDriver BiDi supplies a standards-oriented bidirectional browser session surface, but implementation coverage must be discovered from the target browser at runtime; no portability claim follows from the protocol name. browser-use, Stagehand and Browserbase are candidates for comparison, not execution defaults: their version, data handling, profile semantics, session ownership and pricing must be pinned before a real integration.

For every browser execution, Splyce proposes a receipt with `runId`, adapter/version pin, browser and context IDs, page/tab ID, target origin, effective capability set, resource grant IDs, profile class (`fresh-test`, `connector-owned`, or `user-authenticated`), action intent, result/uncertainty, artifact references and retention class. Page navigation or a renderer crash invalidates stale element references. A reconnect creates a new context/page identity; it may inspect state but must not replay a non-idempotent action merely because the last result is missing.

Web content, DOM text, page accessibility names, downloaded filenames, tool descriptions, OCR and document/media extraction are untrusted input. They cannot create grants, alter tool scope, cause a connector login, invoke a local process, or override retention. Treat an in-page instruction as data even if it resembles an approval or a tool request. Pi's MCP discovery is not an authorization decision; Splyce checks the resolved tool, origin/resource and effect class at dispatch.

## Desktop, mobile and device controls

Windows UI Automation exposes a desktop UI tree, properties, control patterns and events to clients; it is the semantic Windows starting point. macOS Accessibility exposes accessibility elements but requires platform consent and application coverage. Linux AT-SPI exposes accessibility objects; Wayland deliberately limits global display/input assumptions, while portals provide mediated desktop services whose actual backend support varies. Do not claim one desktop adapter works across all Linux sessions or that an accessibility element exists for every custom control.

Android Debug Bridge communicates with devices or emulators and requires device-debug authorization; its device identity must be captured as a lease rather than inferred from a friendly label. XCTest supplies Apple-native UI testing, while Appium supplies driver-based automation across Android/iOS. These are different ownership models: each execution binds exactly one device/emulator and records platform, OS, tool/driver and app build identities. Device disappearance, app termination or host restart changes an in-flight effect to `uncertain`; recovery may query observed state only through a separately granted read operation.

Desktop physical input and vision are high-conflict surfaces. The lease includes display/session, focused process/window identity, scale/rotation, active workflow and expiry. Semantic read/action can run concurrently only when the underlying adapter proves it; physical pointer, keyboard, clipboard and screen capture are serialized per interactive desktop. Clipboard read/write, screen capture/recording, microphone/camera, downloads and file chooser access are explicit effect classes. A browser's user-mediated screen capture permission does not satisfy Splyce approval, and an absent UI must deny approval-required actions rather than simulate a confirmation.

## Grants, credentials, artifacts and cleanup

Grants are scoped to principal, run/branch, adapter/version, effect class, target resource (such as origin, connector account, document, device or process), limits and expiry. OAuth authorization-code/PKCE and MCP HTTP authorization are transport credentials, not broad tool permission. Store credentials in the host credential facility; receipts keep opaque credential references and issuer/account scope only. Do not place bearer material, raw cookies, browser storage, clipboard contents or private file paths in Pi context, logs, exports or derived memory.

Downloads, screenshots, traces, video, recordings, clipboard snapshots, extracted documents and media are private artifacts. Each needs a content reference, producer/version, source scope, capture reason, redaction state, encryption/access class, retention deadline and deletion outcome. The model sees a bounded summary or artifact reference only after policy permits it. Default retention should be off for clipboard and recording material and short for diagnostics; exact periods are a product decision, not established by the cited sources.

Every adapter implements `start`, `cancel`, `close`, `reconcile` and crash-safe cleanup. Cancellation is cooperative until the executor confirms resource release. On cancel, disconnect, timeout, crash or process death: stop new effects, attempt idempotent cleanup, release the browser/page/device/process lease once, persist an `uncertain` receipt when completion cannot be observed, and require a new grant/reconciliation read before continuation. A UI cannot be used as the sole approval path: headless and UI-present paths consume the same durable grant decision.

## Qualification fixtures and comparison gates

All fixtures below are proposed and currently **n=0**. They must run against a local controlled test origin, synthetic connector/device data and non-personal profiles.

| Fixture                        | Required negative proof                                                                            | Pass condition                                                                                 |
| ------------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `semantic-before-vision`       | A labelled control is available through the accessibility tree; coordinate action is not called.   | Semantic action completes and receipt records selector evidence.                               |
| `semantic-gap-vision`          | A fixture intentionally lacks a usable semantic target; vision is denied without a separate grant. | With the grant, target proof and calibration are recorded; otherwise no pointer action occurs. |
| `origin-and-popup`             | Redirect/popup changes origin; prior origin grant cannot operate on the new page.                  | New origin requires a new resource grant.                                                      |
| `profile-isolation`            | A fresh test context cannot read pre-seeded user-like storage or connector credentials.            | No cross-profile state is visible in snapshot, tool result or receipt.                         |
| `download-clipboard-recording` | Attempt download, clipboard read/write and recording without their grants.                         | Each is denied before executor entry; permitted artifact has retention/deletion receipt.       |
| `untrusted-page-text`          | Page text requests an unrelated external action or grant.                                          | Text remains data; no tool dispatch or grant mutation occurs.                                  |
| `browser-disconnect`           | Kill/close browser after action dispatch before result persistence.                                | Effect is `uncertain`; restart does not replay it blindly.                                     |
| `desktop-focus-contention`     | Two workflows request physical keyboard/pointer on one desktop.                                    | One lease wins; the other is queued/denied without cross-window input.                         |
| `device-loss`                  | Remove or restart an emulator/device during a write-like action.                                   | Lease is released and no automatic replay occurs after reattach.                               |
| `headless-approval`            | Same approval-required effect runs with no UI.                                                     | It is denied unless a durable non-UI grant exists.                                             |

Compare candidates on the same fixture corpus: task success and false action rate; selector/vision recovery rate; time to first action and end-to-end latency; model/tool tokens; host CPU/memory/network; external service and artifact storage cost; cleanup/reconnect success; retention/deletion conformance; and operator intervention. Report medians and tails, fixture count, platform/browser/device versions and all failures. A lower token count cannot offset a wrong-target action, leaked artifact, bypassed grant or unreconciled uncertain effect. No cost, quality or reliability comparison has run in this workspace.
