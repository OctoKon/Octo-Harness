## What changed the contracts

| Finding                                 | Evidence                                                                                                                                                                                                                                                                                 | Splyce consequence                                                                                                                                                                                                                                                         |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Requested and served identities diverge | Deprecated or retired IDs redirect to newer models (Google Flash, xAI, DeepSeek, Kimi); OpenAI discovery exposes `shutdown_date`; Mistral preview models can change silently; Foundry Local and LM Studio aliases select hardware-specific variants.                                     | Store requested ID, served revision, lifecycle stage and retirement date separately; a redirected or accepted retired name is never a pin; retirement requires an explicit replacement selection (`C4_served_identity`).                                                   |
| Model × operation restrictions          | OpenAI's GPT-6 Astra/Sol pages document tool calling through Responses only (Codex-sourced, not re-fetched); Anthropic Fable/Opus require adaptive thinking; Gemini 4 Argon uses one unified input/thinking/output window and ignores sampling controls.                                 | Qualification is per model × operation × API family; a model listed under Chat Completions does not qualify coding tools there. Context accounting mode and ignored controls join the model binding (TD-04, TD-32, TD-35).                                                 |
| Forced thinking and reasoning replay    | Kimi K3.1/K2.7, GLM-5.3, MiniMax M3.1 and DeepSeek require preserved reasoning content across tool continuations, and several reject disabling thinking; MiniMax reasoning can exhaust the budget and return empty text with a length finish.                                            | Reasoning blocks replay only through their valid protocol; unsupported effort settings show as unsupported (`C4_effort_binding`); an empty or truncated answer never becomes a completed result (`C4_reasoning_replay`).                                                   |
| Responses lifecycle features            | Async tools let generation continue while a client tool runs, matched later by `call_id`; mid-turn steering acknowledges a steer as queued and can end a response `incomplete` with reason `steered`; WebSocket lanes multiplex conversations; standalone compaction starts a new chain. | A finished response does not mean effects settled: pending async calls bind to receipts or async tools stay unsupported; a `steered` stop is not retried as a failure; provider steer acceptance maps to queued, not consumed (`C4_async_continuation`, `U1_steer_queue`). |
| Anthropic API version 2026-10-21        | New API version rejects sampling fields and some content shapes; SDK 1.0 defaults to it with Bearer authentication; signed compaction blocks and server-tool `pause_turn` continuations.                                                                                                 | API version, SDK, beta headers and auth form are part of the transport identity and an upgrade gate; `pause_turn` is continuation, not completion (TD-21, TD-16).                                                                                                          |
| Hosted orchestration                    | OpenAI Responses offers hosted programs and model-directed subagents; Gemini Interactions stores state by default with background cancellation; xAI Responses stores responses for 30 days by default.                                                                                   | Server-side execution, storage and subagents are separate capabilities with their own consent and retention records; none replaces Pi's loop or inherits generation consent (TD-19, TD-20, TD-50).                                                                         |
| Prompt-cache options                    | OpenAI added explicit breakpoints and 30-minute or 12-hour minimum cache lifetimes on newer models; a cache lifetime is not a deletion deadline.                                                                                                                                         | Receipts record cache mode, lifetime and write tokens; cache TTL, application retention and zero-data-retention stay distinct (`C1_cache_stable_prefix`).                                                                                                                  |

## Windows local inference

| Runtime                                  | Windows status (2026-10)                                                                                                                          | Consequence                                                                                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| llama.cpp v0.7.0                         | Native CPU, CUDA and Vulkan; ARM64 Hexagon NPU developer path; tool calls depend on Jinja templates and parsers.                                  | Record build, backend, template and parser identity; qualify serial and parallel tool calls separately.                                |
| Ollama v0.40.11                          | CUDA, ROCm and Vulkan lanes; the local service can also invoke cloud models; Responses is non-stateful (no `previous_response_id`).               | A loopback endpoint does not prove local execution (`C4_loopback_locality`); stateful Responses stays unsupported.                     |
| LM Studio 0.4.26                         | App, build and runtime extension versions differ; runtime auto-update defaults on; "default" tool mode rewrites tool messages into user messages. | Pin runtime extensions and disable silent updates; test native versus rewritten tool history.                                          |
| vLLM 0.32 / SGLang 0.5.22                | No native Windows support upstream; WSL/Linux or community forks only.                                                                            | External-service candidates with their own platform cells, not packaged Windows workers.                                               |
| ONNX Runtime GenAI, Windows ML, DirectML | Library-level inference with WinML/DirectML execution providers; no OpenAI-style HTTP server; possible usage telemetry.                           | Separate runtime/EP/driver identity from any HTTP host; telemetry controls qualify before use; EP downloads need provisioning consent. |
| Foundry Local SDK 2.2.1                  | SDK and CLI HTTP serving are separate; catalog aliases pick hardware variants.                                                                    | Hardware auto-selection cannot silently change an admitted model revision.                                                             |
| OpenVINO GenAI 2026.4 / OVMS             | Native Windows x64 CPU/GPU/NPU lanes; OVMS serves `/v3/chat/completions` and can fall back to unguided generation when a schema fails to load.    | Strict extraction rejects unavailable guidance instead of accepting weaker output.                                                     |

## Open-weight candidates

Qwen3.8-27B (Apache-2.0), Qwen3-Coder-30B-A3B (Apache-2.0), Devstral Small 2 24B (Apache-2.0), gpt-oss-20b (Apache-2.0) and GLM-4.7-Flash (MIT) are midrange local candidates; Qwen3-Coder-Next (80B total) is a workstation candidate. Licenses are per checkpoint: Qwen3.8-Flash-Next uses the Qwen Community License with commercial conditions, and the large DeepSeek V4.1 Flash, MiniMax M3, Kimi K3 and GLM-5.3 weights carry their own terms and exceed ordinary desktop tiers despite small active-parameter counts. None has Splyce Windows fit, tool or quality evidence.

## Named acceptance cases

Owners are listed in the [task plan's named case table](../design/team-delivery-plan.md#named-case-ownership).

| Case                    | Required observation                                                                                                                                                                                                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `C4_served_identity`    | A binding to a redirected, retired or preview alias records requested ID, served revision and lifecycle stage separately; a served revision change or announced retirement blocks the binding until the user explicitly selects a replacement, with no silent remap.                           |
| `C4_reasoning_replay`   | On a forced-thinking provider, a tool continuation replays the prior reasoning blocks through the valid protocol; disabling thinking where unsupported reports unsupported; a response that exhausts its budget with empty text and a length finish is recorded as truncated, never completed. |
| `C4_async_continuation` | With async tools either unsupported or enabled, a response that finishes while a tool is pending never marks the action settled; a late result binds to its original `call_id` receipt; a `steered` incomplete response is continued once, not retried as a failure.                           |
| `C4_loopback_locality`  | An all-local profile pointed at a loopback runtime that proxies a cloud model is rejected, because locality comes from admitted route and executor evidence rather than the loopback address.                                                                                                  |
