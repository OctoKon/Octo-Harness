# Extended internals: capability gap closure (2026-10-25)

**Active product scope:** Splyce keeps agent execution and stored state local. Each inference role may use a local runtime or an explicitly authorized cloud API profile with recorded endpoint, model/revision, and egress scope; it never silently switches provider or falls back. Hosted memory and executors below remain comparative research, not product dependencies. [Current master plan](../../../MASTER-PLAN.md).

Documentation-verified only; local quality, latency, cost, and agent gains are **n=0**.

**Serena** is an MIT MCP toolkit for language-server-backed semantic retrieval, editing, refactoring and debugging. Reuse symbol-addressed operations, while retaining URI/document-version/workspace guards: LSP answers are not durable evidence. **RTK** is a Rust pipeline that intercepts shell/tool output before model context. Reuse bounded presentation only when every compressed view links to a source artifact, command, exit code, omitted ranges and lossless retrieval route. **OpenViking** is Volcengine's AGPL-3.0 context database exposing resources, memories and skills through stable `viking://` paths; its filesystem-like addressing is useful, but automatic L0/L1 summaries and extracted memories remain derived data subject to provenance/deletion checks. **OpenSandbox** exposes sandbox command/file/code APIs and MCP: use it only behind a harness-owned authorization policy, since sandbox isolation is not authorization.

**Streams and providers:** LiteLLM normalizes providers behind an OpenAI-shaped API with streaming, retries and fallbacks; Ollama offers native local/cloud APIs and OpenAI compatibility but documents no strict API versioning. The harness must retain an internal provider event stream with model/endpoint/revision, text/tool/reasoning delta, finish/error and usage events. It must not assume compatible endpoints preserve tool-call streaming semantics. vLLM's [official OpenAI-compatible-server documentation](https://github.com/vllm-project/vllm/blob/main/docs/serving/online_serving/openai_compatible_server.md) is now resolved; it is a provider endpoint, not a coding-agent runtime, and its API-key option does not secure every endpoint.

**Durable work:** Temporal reconstructs workflow state by deterministic replay of event history, with external I/O/LLM calls in recorded Activities. DBOS checkpoints annotated workflow steps in Postgres. Restate offers keyed virtual objects and per-ID workflows. Reuse append-only history, idempotency keys and explicit retention; do not use a retrieval or memory graph as an execution log. Replay-compatible workflow versioning is a hard prerequisite.

**Optimization:** GEPA is an official reflective text-evolution system for prompts, code and instructions against an evaluator. Meta-Harness is a research outer loop that searches harness code; the canonical research repository is `stanford-iris-lab/meta-harness`, while similarly named implementations must not be conflated. Darwin Gödel Machine is research on open-ended self-improving agents. MESH-Harness and AutoHarness are adjacent research candidates. Reuse only the guarded pattern: candidate diff → fixed evaluator → trace/provenance → held-out non-regression → reviewed promotion. No optimizer may self-authorize plugins, tools or policy.
