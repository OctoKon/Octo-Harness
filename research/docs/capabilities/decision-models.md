# Local decision models: Laya, D3 and abstention

Reviewed **2026-10-25**. Public-source research, selected pinned source inspection and proposed experiments only. Splyce runtime results, accuracy, latency and savings are **n=0**. [Source ledger](../evidence/decision-model-sources.json). This is optional B8 research under the [master plan](../../../MASTER-PLAN.md), [qualification register](../design/qualification-register.md) and [efficiency research](efficiency-and-recursive-improvement.md), not a new execution loop or adoption decision.

## Boundary and smallest useful baseline

A typed decision model returns a distribution over supplied choices, yes/no or score bins instead of generating an answer token by token. That may reduce repeated generation for bounded classification; it does not establish reasoning quality, calibrated confidence or useful agent-level savings. Pi retains its loop. Host policy checks grants, and actual verifier receipts certify completion. A classifier cannot grant permission, certify an effect, replace authentication or silently discard valid tools/evidence.

Start with deterministic rules for known schema facts; compare a local linear classifier over existing features and constrained output from the already loaded generator. Load a separate decision model only if repeated work repays installation, cold load, memory and orchestration. Agent execution, memory, and state remain local. Generation, extraction, embeddings, reranking, and decisions require a recorded local or explicitly authorized cloud profile; unavailable workers return a visible unavailable/abstain outcome without a silent fallback.

## Chain 1: Laya's single pass becomes a checkpoint and candidate-budget problem

**Mechanism → source:** the canonical [Laya repository, DEC-01](https://github.com/NandhaKishorM/laya) describes encoder-based typed classification, probability outputs and reinforcement learning against proper scoring rules. Its English and typed-decision checkpoints use ModernBERT-large (421M); multilingual uses mmBERT-base (322M). These are distinct checkpoint contracts, not one universally equivalent model. Language coverage is an upstream claim to test on actual code, mixed scripts and user text.

**Limit → counterevidence:** [Fast Models, Slow Evidence v1, DEC-03](https://arxiv.org/abs/2610.02267v1) reports a paired study across 11 harness decisions. Neither evaluated model exceeded chance on zero-shot model routing. Laya changed 30% of answers under option reversal and degraded with numerous similar tool candidates. These are the paper's selected models/tasks, not a verdict on every later Laya revision. Current upstream fine-tuning and wider option budgets are possible mitigations; they also change compute and require a fresh comparison. The [released evaluation artifacts, DEC-04](https://github.com/David-DL-Space/sys1-eval) make the pipeline and its self-audit inspectable.

**Local burden → source observation:** [pinned router, DEC-02](https://github.com/NandhaKishorM/laya/blob/73c9c0cd7ef9bcd22bdb727042e04164a64bd073/laya/router.py) lazily builds checkpoints and defaults to two resident models; preloading raises capacity to accommodate loaded models. Routing time alone excludes checkpoint loading and inference. Python, PyTorch, tokenizer/config and model assets count toward footprint. Pin each checkpoint independently, inspect its actual license and hash, and prove offline loading rather than allowing a first-use Hub download. The [code license, DEC-08](https://github.com/NandhaKishorM/laya/blob/73c9c0cd7ef9bcd22bdb727042e04164a64bd073/LICENSE) is Apache-2.0; this inspection does not certify every model asset or conversion.

**Splyce use → decisive rejection:** test advisory tool ranking or non-destructive task categorization. Preserve all candidates and an abstain path. Evaluate full-schema decisions against a separately measured retrieval shortlist: report shortlist recall before downstream accuracy, including cases where the correct choice is absent. Reject if apparent speed depends on losing valid choices, if option permutations change decisions beyond the preregistered tolerance, or if full-task quality falls below the simpler baseline.

## Chain 2: D3's local weights do not inherit a hosted service's contract

**Mechanism → source:** [D3-edge model card, DEC-05](https://huggingface.co/vllm-sr/d3-edge/tree/c454ee39b862248d70abd7f84195d2f54ffe6d43) describes a 0.59B multimodal Decision 3.0 model, including a vision encoder, returning choice/yes-no/score probabilities without text generation. Text and vision capability need separate qualification. The card's AutoModel quickstart uses custom model code; downloading weights is insufficient without reviewing and pinning that code, processor and dependencies. Its [actual model license, DEC-06](https://huggingface.co/vllm-sr/d3-edge/blob/c454ee39b862248d70abd7f84195d2f54ffe6d43/LICENSE) is Apache-2.0; retain notices and validate the complete distribution.

**Limit → counterevidence:** the publisher itself says edge is not on the text leaderboard's parameter/score Pareto frontier. Its measured serving modes have substantially different memory and load costs. A small parameter count and a warm accelerator timing therefore do not establish lightweight desktop operation. The [official model-selection documentation, DEC-07](https://vllm-sr.ai/docs/next/model-runtime/choose-a-model/) distinguishes model sizes and quantized formats; a revision-specific parity result is not accuracy equivalence across tasks or platforms. No D3 implementation code path was audited here and no model was executed.

**Local burden → mitigation:** inspect immutable model/custom-code revision, tokenizer, image/video processors, native libraries, serialization and quantization compatibility before admission. Prefer a text-only experiment first; do not add image/video dependencies for a text routing use case. Compare in-process inference with an already qualified local service only where that service actually supports the decision architecture. A hosted Decision API is a separately unqualified cloud profile, never an implicit execution path or fallback. API shape, model name and weights identity do not prove matching predictions.

**Splyce use → decisive rejection:** compare the smallest qualifying D3 checkpoint against Laya, rules and the existing generator on identical schemas and hardware. Reject if loading/idle contention outweighs warm savings, if custom-code or asset licensing is unresolved, or if schema/candidate changes yield uncalibrated confident errors. No model family automatically wins because its largest member tops an upstream board.

## Chain 3: confidence cannot supply missing information

**Problem → mitigation research:** [LAVOIR v1, DEC-09](https://arxiv.org/abs/2609.30706v1) augments a single-pass decision encoder with candidate information slots and estimated value of asking about them. It tackles forced guesses when a message lacks discriminating facts. The paper reports gains from selective questions and a Gini-based cap on predicted information value. Its controlled schemas, oracle comparisons and reported accelerator timings do not establish general question quality or desktop economics.

**Countercondition → local contract:** a confidence threshold alone cannot recover a missing fact, detect every out-of-distribution input or guarantee calibration after schema/language shift. Compare fixed clarification rules, entropy/margin abstention, calibrated classifiers and LAVOIR-style predicted value on held-out schemas. Any synthetic-data teachers, verification models, fine-tuning and calibration must run locally if adopted; the paper's training process is not an authorized hosted dependency. Code/checkpoint/license inspection remains open for LAVOIR. Questions are user interaction with a cost, not a free accuracy improvement.

**Splyce use → decisive rejection:** allow an advisory request for clarification or escalation to the qualified local generator, constrained by the original task and grants. Measure useful-question rate, residual error, user burden, abstention coverage and total latency. Reject indiscriminate questioning, confident forced guesses, or question policies tuned on their own evaluation cases.

## Paired qualification contract

Register one experiment per use case before implementation. No record below claims executed fixtures.

| Experiment | Fixture and comparison                                                                                                                                            | Required observations and failure condition                                                                                                                                                                 |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DEC-A      | Frozen schemas, disjoint projects, held-out labels; rules, linear classifier, existing local generator, Laya and D3                                               | Accuracy/macro-F1 by class, Brier/log loss, calibration and risk-versus-coverage; reject quality loss or no total-cost gain at the declared quality floor.                                                  |
| DEC-B      | Same correct tools with permutations, aliases, near duplicates, increasing schema sizes, no valid choice, mixed languages, long/truncated input and missing facts | Stable IDs and abstention; measure full-schema accuracy and shortlist recall separately. Confidence never overrides host policy.                                                                            |
| DEC-C      | Cold model start, warm single calls, batches, concurrent generation, cancellation, malformed output, missing/corrupt assets and worker restart                    | Install/download bytes or API egress/retention record, cold/warm/p95 full-task latency, peak/idle local cost where applicable, cleanup and visible failure; local-only profile observes no hosted requests. |
| DEC-D      | Loaded Pi user task with routing disabled/enabled and held-out correctness verifier                                                                               | Include preprocessing, screening, reloads, fallback generation, questions, retries and failed runs. Completion requires final-revision receipts. Reject a gate-only win that harms completed-task quality.  |

Separate calibration/training, threshold selection and final untouched evaluation. Use paired tasks, report sample size and uncertainty, preserve failures, and preregister the admissible quality margin and resource budget. The self-audited study corrected omitted screening cost, gate accuracy mistaken for end-to-end quality and in-sample thresholds; these are direct reasons to measure the whole chain. Model/version/schema drift reopens admission. Do not transplant paper thresholds or claim current calibrated probabilities from a training objective alone.
