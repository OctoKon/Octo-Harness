# Memory mechanisms: evidence chains and qualification decisions

**Reviewed 2026-10-25. Research only; all Splyce runtime, model, quality and cost results are n=0.** This follows the [memory frontier](cross-session-memory.md), [context research](context-retrieval-and-memory.md), [Pi source contracts](../foundations/pi-source-contracts.md) and [implementation contracts](../design/implementation-contracts.md). The [MR source ledger](../evidence/memory-review-sources.json) distinguishes selected code from documentation and paper results. No backend was installed. Observing a missing guarantee in selected methods does not prove that every deployment lacks it.

The useful first milestone is scoped, cited recovery through the loaded Pi entrypoint. Start with an existing qualified store, lexical search, a small task capsule and ID-based source expansion. Add a graph or learned sparse route only when paired evidence establishes a benefit. “Native” means one Splyce-owned lifecycle and policy boundary; it does not require a new storage engine or another agent loop.

**Binding deployment rule:** Splyce keeps memory and state local. Generation, extraction, embedding, and reranking require recorded local or explicitly authorized cloud profiles with no silent provider fallback. Hosted memory and executors below remain comparative upstream research only. A remote-compatible API is not acceptance evidence for a selected operation. Pin licenses for selected code and model weights before adoption.

## 1. claude-mem: progressive recall can save disclosure while hiding omissions

**Chain:** [search contract, MR-01](https://github.com/thedotmack/claude-mem/blob/abd9aaab61995c53060a6bd15ce41e236f7c53e3/docs/public/usage/search-tools.mdx) → [search orchestrator, MR-02](https://github.com/thedotmack/claude-mem/blob/abd9aaab61995c53060a6bd15ce41e236f7c53e3/src/services/worker/search/SearchOrchestrator.ts) → [semantic filtering and hydration](https://github.com/thedotmack/claude-mem/blob/abd9aaab61995c53060a6bd15ce41e236f7c53e3/src/services/worker/search/strategies/ChromaSearchStrategy.ts).

**Documented strength:** search exposes a compact index, timeline exposes neighbours and later corrections, and `get_observations` expands selected IDs. This separates discovery cost from evidence disclosure. Upstream token estimates are not measured Splyce savings. An observation remains generated content; expanding its narrative is not equivalent to recovering original tool output.

**Source finding and counterevidence:** the pinned orchestrator uses SQLite for filter-only queries or disabled Chroma. With configured Chroma, errors become `ChromaUnavailableError`; genuinely empty categories are supplemented from SQLite. The semantic strategy has an implicit recency window, explicit bypass/date handling and project filtering before candidate hydration. Thus an older description of a universal failure fallback with the query stripped is stale for this revision. These branches mitigate empty recall and age bias; they do not prove complete recall or caller authorization.

**Inference:** a missing identifier, exception qualifier or source range discarded by extraction cannot be restored by fetching more observation text. A title may also discourage expansion of the right observation. A timeline helps detect correction only if it includes the correction and the model follows it. Project-name matching is useful eligibility metadata, but the host still has to bind an authorized workspace identity to every search and ID expansion.

**Alternative and Splyce consequence:** retain redacted source artifacts independently; index observation titles and original lexical text, preserve source IDs and distinguish observation expansion from source expansion. Reuse the three-stage interface, with explicit degraded/unavailable status and branch-aware scope. Do not adopt the whole worker/SQLite/Chroma stack merely to obtain that interface.

**Falsifiable check CM:** bury a rare literal in an old original artifact while omitting it from a generated observation; add a later correction outside the first timeline window. Compare summary-only search, original-text lexical search and progressive expansion at equal supplied-token budget. Record omission, wrong-current-answer, expansion calls and total model tokens, including extraction. Reject a route that asserts a summary as original evidence or presents provider failure as a successful empty search. Test old exact matches both with recency enabled and bypassed.

## 2. Mem0: salient extraction is useful, but paper semantics are not today's API

**Chain:** [OSS component configuration](https://docs.mem0.ai/open-source/overview) → [paper sections 2, 4.3–4.5, MR-03](https://arxiv.org/html/2504.19413v1) → [pinned Python implementation, MR-04](https://github.com/mem0ai/mem0/blob/2c81af3bbe27d9bccb09c772d583df9e9be72ee5/mem0/memory/main.py).

**Paper strength and counterevidence:** the paper evaluates salient conversational memories and a graph variant on LoCoMo. Its extraction/update design uses recent messages, a summary and similar memories; the LLM selects ADD/UPDATE/DELETE/NOOP. Its own full-context comparison has higher overall judge score than either Mem0 variant. Graph memory adds latency and memory footprint. The paper's query latency and construction analysis are separate; neither establishes amortized coding-agent lifecycle cost. These are author-reported benchmark results, not independent replication or Splyce evidence.

**Source finding:** current `Memory._add_to_vector_store` describes a phased additive pipeline: recent-message context, similar-memory retrieval, one structured extraction call, batch embedding, deduplication and persistence. `infer=False` instead embeds and stores non-system message content. Do not infer current correction or graph behavior from the older four-operation paper. The selected add path is not a graph implementation review. An entity-store helper in this file is not proof of arbitrary graph traversal.

**Limit and follow-up:** `delete` delegates to `_delete_memory`, which deletes the vector and writes a DELETE history record containing its previous value. Entity-link cleanup is best effort. `delete_all` batches retrieval/removal, a useful mitigation against truncated enumeration. These are concrete lifecycle operations; a successful logical removal still does not certify erasure of history, source messages, every derived store or backups. This distinction is a retention requirement, not a claim about all hosted Mem0 deployments.

**Alternative and Splyce consequence:** use explicit append-only supersession plus source references for corrections; separately implement scoped logical suppression and a verified physical-retention workflow. Qualify either a fully local extraction-enabled Mem0 adapter or its non-inference storage path against the same source-preserving baseline. Record the selected language SDK: reading Python does not establish TypeScript parity. Self-hosting lets the operator choose model services; defaults and an “OpenAI-compatible” label do not establish a fully local configuration or structured-output compatibility. Replace hosted defaults; unavailable local models must fail explicitly without remote fallback.

**Falsifiable check M0:** ingest a decision, a qualified exception and a later correction; query current and historical state after restart. Compare inference enabled/disabled with identical source artifacts. Inspect scoped export, history and enabled derived stores before/after deletion and restore. Invalid extractor JSON, timeout and partial persistence must have distinct measured outcomes; a stored empty extraction is not evidence that the source contained no facts. Measure extraction, embedding, retrieval, answer and repair cost separately. Reject deletion completion while retained text remains inside the promised purge scope.

## 3. HippoRAG 2: graph diffusion helps association but can discard useful seeds

**Chain:** [paper method and ablations, MR-05](https://arxiv.org/html/2502.14802v1) → its appendices E/F (error/cost analysis) → [pinned `retrieve`, `rerank_facts` and `delete`, MR-06](https://github.com/OSU-NLP-Group/HippoRAG/blob/d5c8329422e0a0b834a15874545cb6a74b4f9b26/src/hipporag/HippoRAG.py).

**Paper strength and limit:** passages and extracted phrases share a graph; query-to-triple matching, LLM recognition filtering and Personalized PageRank retrieve passages. Appendix E examines 100 imperfect-recall cases, not a random sample of all queries: recognition filtering and graph ranking both contribute failures. Appendix F reports offline indexing in specific GPU/cloud conditions; it is not a desktop end-to-end cost result. The paper's multi-hop evidence motivates an experiment, not a default memory backend or biological-memory claim.

**Counterevidence in implementation:** `retrieve` explicitly falls back to dense passages when recognition returns no facts, retaining source-passage retrieval rather than answering solely from generated triples. `delete` tracks shared triple/entity sources, removes deleted-source contributions and persisted indexes, and rejects deletion for legacy graphs lacking source-aware edge provenance. Calling this revision incapable of source-aware deletion would be wrong. These safeguards still do not establish cross-store crash atomicity, backup erasure, tenant authorization or correction-time semantics.

**Inference and alternative:** a wrong nonempty seed set can still propagate to plausible irrelevant passages; dense fallback only on an empty set does not resolve that case. Compare graph candidates with the union of lexical, dense and recency candidates, preserving their independent ranks. A typed receipt/observation provenance graph can support navigation without adopting OpenIE or PPR. Multi-hop prose retrieval and current mutable code retrieval need separate strata.

**Splice point and falsifiable check HR:** keep HippoRAG behind M2's retrieval port, returning source IDs and graph seeds. Use two-to-four-link synthetic evidence chains, high-degree distractors, rare identifiers and corrections. Ablate dense only, lexical plus recency, graph without recognition, and full graph with the same answer model and supplied-token budget. Record whether the correct source was lost at extraction, seed filtering or diffusion. Remove one of two shared supports, then the last support; compare rebuilt and incremental eligible evidence after restart. Reject any stale deleted support; promote graph ranking only by the gate below.

## 4. Graphiti: temporal invalidation is stronger than recency, conditional on extraction

**Chain:** [runtime/model requirements, MR-07](https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/README.md) → [`_apply_temporal_invalidation` and timestamp extraction, MR-08](https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/graphiti_core/utils/maintenance/edge_operations.py) → [`add_episode`, `search_`, `remove_episode`, MR-09](https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/graphiti_core/graphiti.py).

**Documented strength:** episodes, facts and temporal intervals preserve changing assertions; group IDs partition graph data. The README makes the operator responsible for ingestion, tenancy and access control, and cautions that smaller models can struggle with structured output. A configured local endpoint is therefore not a qualified local extraction profile. The selected runtime needs Python, a supported graph database, LLM and embedding services; embedded options do not eliminate version/platform qualification.

**Source finding:** temporal invalidation compares validity intervals after candidate resolution; newer valid facts can expire older ones, including out-of-order arrival. Timestamp extraction is model-assisted and can fail. Consequently, correct date comparison does not establish correct entity resolution, contradiction identification or inferred dates. “Latest ingested” and “valid at requested time” remain different queries.

**Counterevidence and residual limit:** `remove_episode` keeps facts supported by other episodes, removes unsupported nodes/edges and rebuilds surviving entity summaries. This is substantially more than deleting an episode row. The rebuild exception path retains the previous summary, however; removal completion cannot alone certify regenerated derived text. External caches and backups are outside the selected method's proof. No universal Graphiti deletion defect is inferred.

**Alternative and Splyce consequence:** retain explicit source-authored supersession and validity assertions first; treat extracted temporal edges as proposals. Require model-failure state and provenance on the returned fact, with source hydration before use. Introduce this graph only for recurring temporal/relational queries that simpler current/historical records cannot answer economically.

**Falsifiable check GT:** ingest the same dated decision and correction in both arrival orders, include unknown dates and overlapping qualified assertions, and query “current” versus “as of.” Remove one of two supporting episodes and then the last; query facts and surviving summaries after a deliberately unavailable summarizer, restart, index rebuild and backup restore. Require either a clean rebuilt projection or an explicit blocked/incomplete state. Compare temporal correctness and full lifecycle cost with explicit supersession plus lexical retrieval.

## 5. OMP Mnemopi: the closest reuse candidate still has host and runtime boundaries

**Chain:** [pinned package README, MR-10](https://github.com/can1357/oh-my-pi/blob/0b5c27ab24719c86a5986b95ee55f4e75bc1aaa0/packages/mnemopi/README.md) → [facade](https://github.com/can1357/oh-my-pi/blob/0b5c27ab24719c86a5986b95ee55f4e75bc1aaa0/packages/mnemopi/src/core/memory.ts) → [`forgetWorking` and model reconciliation, MR-11](https://github.com/can1357/oh-my-pi/blob/0b5c27ab24719c86a5986b95ee55f4e75bc1aaa0/packages/mnemopi/src/core/beam/store.ts). Reuse the [foundation compatibility finding](../foundations/pi-foundation.md#reuse-memory-too-qualify-mnemopi-before-writing-a-new-backend), backed by [database source, MR-12](https://github.com/can1357/oh-my-pi/blob/0b5c27ab24719c86a5986b95ee55f4e75bc1aaa0/packages/mnemopi/src/db.ts) and the existing PI-09 manifest record.

**Documented strength:** local SQLite, lexical recall, optional ONNX/compatible remote embedding and optional LLM services support a no-cloud starting configuration. Banks are exposed by the library; host wrappers determine project/global visibility. The package does not bundle a GGUF generator. Its local generation role therefore needs an independently qualified backend or callback, while heuristic paths need their own correctness comparison.

**Source finding and counterevidence:** facade `forget` delegates to working-memory deletion. The store transaction deletes the matching session row, purges working-memory artifacts and invalidates caches. Model reconciliation detects a changed stamped embedding model and schedules rebuilding; interrupted rebuilds re-enqueue missing vectors. These are useful existing mechanisms, not reasons to rewrite them. They do not certify all episodic/consolidated descendants are removed by `forget`, nor that every embedding-contract change is detected by a model-name check.

**Alternative and consequence:** compare a qualified Bun distribution/service integration against a Node-compatible existing backend before choosing. The pinned manifest requires Bun and workspace/native dependencies; `db.ts` uses `bun:sqlite`. That source constraint defeats an unqualified “drop-in Node package” claim but does not prove that a supported bridge is impossible. Keep one policy/receipt owner and include service supervision, native binaries, shutdown, migration and installed-platform cost in F0/R1.

**Falsifiable check MP:** retain original evidence, consolidate it, forget it, reopen with an empty Pi context, and query every enabled working/episodic/cache route. Switch embedding revision/instructions with equal dimensions, interrupt reindexing and verify generation isolation. Change banks and session/branch identity through the real host wrapper. Reject cross-scope disclosure, uncited consolidation, incomplete purge reported complete or mixed incompatible vectors. Preserve a no-embedding recovery route while optional models are unavailable.

## Minimum useful baseline and exact experimental gate

**Proposed M1/M2 baseline:** reuse a local store passing F0/C3; capture committed redacted receipts with source references, Pi session plus Splyce branch anchor, stable scope and extraction revision. Persist a small cited task capsule and source-text lexical index. Return IDs first, allow bounded timeline/source expansion, append explicit correction links, authorize before retrieval/cache lookup and after hydration. Tombstone immediately, track purge of every enabled projection, and reapply tombstones before restored stores serve queries. Pi retains its generation loop. Extraction, generation, embeddings, and reranking use qualified local or explicitly authorized cloud profiles; cloud inference never turns storage into hosted memory. Dense, graph and learned sparse retrieval are optional routes over the same eligible sources, never separate authorities.

**Local/offline acceptance:** enumerate every process, database, model artifact, license, initialization download and endpoint. After explicit installation/provisioning, disconnect external networking and clear runtime caches while preserving only declared installed artifacts. Run cold startup, real generation/extraction and every enabled embedding/reranking route, capture, restart recovery, correction, retention expiry and deletion/restore. Observe zero external connection attempts, including telemetry and automatic model downloads; test missing model files and local-service failure as explicit unavailable outcomes. No cloud fallback or account/API credential may be necessary. Cold-cache runs cannot rely on undeclared model caches. Storage and recovery remain local throughout the lifecycle.

**Proposed preregistration:** freeze a public/synthetic corpus, queries, expected evidence IDs, model revisions and budget before candidate tuning. Use 240 held-out recovery queries, 40 each for exact old identifiers, paraphrase, two-to-four-hop chains, temporal corrections, empty-context/branch recovery and no-answer cases. Separately run 60 lifecycle cases covering scope/revocation, shared-support deletion, derived text/cache removal, interrupted capture, interrupted reindex and restore; exercise every enabled route. These counts and thresholds are proposed decision rules, not results or universal sample-size guarantees. Report confidence intervals and do not count synthetic variants as independent real projects.

| Decision                                     | Exact proposed condition                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Qualify minimal memory                       | All 60 lifecycle cases and local/offline acceptance pass; every supported answer resolves to eligible original evidence; each of the six recovery strata scores at least 36/40; every no-answer fixture either abstains correctly or supplies the designated evidence. The real loaded Pi restart/branch path must pass, beyond backend component checks.                                                                          |
| Promote dense, graph or learned sparse route | All hard lifecycle gates pass; paired 95% bootstrap lower bound for improvement on its preregistered target stratum is above zero; lower bound on overall answer-correctness change exceeds -2 percentage points; no additional unsupported authoritative answer. Use 10,000 fixed-seed resamples and publish denominators.                                                                                                        |
| Enforce cost/operations limit                | Before measurement, declare workload size, reads per write, hardware and maximum total cost/latency. Candidate must fit those limits and have no more than 1.25× baseline p95 recovery latency and amortized lifecycle cost. Include extraction, embeddings, graph construction, query models, hydration, answer, correction, deletion/rebuild, storage and operator intervention. Otherwise retain as an optional research route. |
| Reject or remain inconclusive                | Any scope/deletion/provenance violation rejects deployment regardless of mean quality. A failed confidence bound or missed cost bound prevents promotion. If the corpus is too small, confidence is wide, a service is unavailable or usage is missing, report inconclusive/n=0 as appropriate; do not select another convenient metric after observing results.                                                                   |

Measure the full cost ledger as `capture + extraction + index/build + Q × (search + expand + answer) + correction + purge/rebuild/restore + storage + operation`, for declared Q. Report token/monetary cost and CPU, memory, disk, network, p50/p95 and cold-start time separately; missing provider usage is unknown. Evaluate both raw-source retrieval and summary retrieval so compression losses remain visible. A sparse route must also test index/filter equivalence and drift, using the [sparse research](sparse-retrieval-and-coordination.md), rather than borrowing a graph result as its own qualification.

No implementation, provider compatibility run, installed-package check or comparative trial was performed. Runtime, lifecycle and quality conclusions remain unqualified until these experiments run.
