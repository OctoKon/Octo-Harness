# Provider API conformance and acceptance matrix

**Reviewed 2026-10-25. Documentation/source observations only; provider calls, end-to-end tests and installed-adapter measurements n=0.** Splyce supports explicitly selected local **and** cloud inference while application execution, sessions, policy and authoritative state remain local. Cloud dispatch needs per-role endpoint/data-class permission. Barebones setup installs no optional adapter, SDK or model automatically; qualify actual Pi packaging before promising selective dependency removal. [Provider/profile/session design](../design/providers-profiles-and-sessions.md), [pinned Pi audit](../foundations/pi-provider-session-contracts.md), [PST ledger](../evidence/pi-provider-session-sources.json) and [PAPI-01–PAPI-12](../evidence/provider-api-sources.json).

Here “completions” means **Chat Completions**. Pi's `openai-completions` invokes `chat.completions.create`; it does not establish support for legacy text `/completions`. Compatibility declarations, matching JSON fields and a model appearing in a picker do not qualify an actual provider/operation.

## Transport and history are separate compatibility dimensions

OpenAI Responses SSE is the baseline documented path; [WebSocket mode](https://developers.openai.com/api/docs/guides/websocket-mode) is separately optional. Connection-bound continuations can fail when referenced response state is unavailable. Reconnection/full-history replay requires current authorization and must not replay a completed local effect. A Pi JSONL session, provider response ID and WebSocket connection/stream identity are different records. Do not infer that every `openai-responses` endpoint supports WebSocket because the Codex adapter does.

Google's old thought-signature page now points to the [thinking guide](https://ai.google.dev/gemini-api/docs/thinking). It distinguishes `generateContent` signature metadata on parts from Interactions' dedicated thought steps. The pinned Pi path is the former. Preserve compatible opaque metadata for its originating provider/model, never fabricate a signature or blindly attach one to another vendor's message. Cross-provider conversion must handle unsupported private reasoning metadata explicitly without pretending the converted conversation is byte-identical.

Local/native protocols are additional **candidate operations**, not assumed Pi chat API IDs:

| Candidate                | Official behavior                                                                                                                                               | Admission boundary                                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ollama native generation | `/api/generate` can emit newline-delimited JSON, including terminal `done`; [streaming documentation](https://docs.ollama.com/api/streaming).                   | NDJSON requires its own parser and fixture. Pi's documented OpenAI-compatible Ollama route does not establish a native NDJSON adapter. Keep missing native support explicit.          |
| Ollama embeddings        | `/api/embed` returns vectors; `truncate` defaults true and can instead reject oversized inputs; [embed reference](https://docs.ollama.com/api/embed).           | Optional embed adapter needs output count/dimension/finiteness/model/truncation checks and a complete index contract. A generation endpoint cannot imply it.                          |
| TEI embedding/reranking  | TEI documents `/embed` and `/rerank` for the appropriate loaded model; [official quick tour](https://huggingface.co/docs/text-embeddings-inference/quick_tour). | Independently selected operation/service/model. Preserve candidate identities, scoring semantics and failure states; no vector-store/RAG installation follows from declaring support. |

Cloud embedding/reranking APIs remain an open operation-specific frontier. None is inferred from an advertised chat family, and no hosted retrieval/memory service becomes required. Local state can contain derived results, while explicitly permitted inference inputs/results still traverse the selected provider boundary.

## Common failure, usage and credential contract

The following are proposed Splyce requirements to apply to **every selected provider × model/deployment × API/transport × operation × installed platform**. They do not assert that upstream SDKs already enforce them.

| Concern                         | Required behavior                                                                                                                                                                      | Decisive failure observation                                                                                                                                        |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission / credentials         | Check current role/data-class/endpoint grants before request construction or credential helper execution. Bind non-secret credential identity and refresh behavior; do not log values. | Wrong key, expired OAuth, wrong deployment/region/project or revoked grant is explicit; no alternate provider or helper executes silently.                          |
| Partial stream / tool arguments | Order chunks by protocol identity; buffer incomplete arguments, validate final schema and original tool grant before local dispatch.                                                   | Partial/malformed/interleaved tool calls cannot execute; unknown mandatory semantics or missing terminal event fails visibly.                                       |
| Error / retry                   | Distinguish 401/403, 429, 5xx, transport timeout, schema, policy, content block and terminal provider errors. Retry only under the admitted safe request policy.                       | After visible output or an observed/uncertain tool effect, no blind whole-turn retry. SDK retry and host retry budgets are recorded together.                       |
| Usage / cost                    | Preserve reported input/output/cache/reasoning counters with provider definitions, cumulative/delta semantics and attempt identity; estimates stay separate.                           | Missing final usage after disconnect remains unknown. No double-counted cumulative usage, fabricated zero tokens or catalog-price claim of measured billing.        |
| Cancellation                    | Stop admission, signal transport, cancel/drain local work, record provider acknowledgement separately from local stop.                                                                 | A closed socket does not prove remote cancellation or zero charge. Late output cannot publish under a revoked role/config revision.                                 |
| History conversion              | Preserve text, images, tool-call/result pairing and eligible provider-specific metadata. Validate token/context limits and role constraints before send.                               | Cross-provider switch or resume cannot silently drop tool results, send disallowed history, fabricate reasoning signatures or authorize stored remote continuation. |
| Retention / locality            | Keep operational state locally; enumerate intentional remote inputs/cache/response objects and applicable retention limits.                                                            | `store: false`, local session storage or a private-looking endpoint is not proof of provider-side erasure or zero egress.                                           |
| Installation / ownership        | Install only explicitly selected adapter dependencies and admitted build steps; distinguish bundled Pi code from optional assets and active workers.                                   | Enabling a role causes no implicit SDK/model install. Disabling releases owned resources while preserving unrelated shared services.                                |

The [PST audit](../foundations/pi-provider-session-contracts.md) identifies important source limits: model setters/RPC need a stream-transition fence, credential configurations can execute helper commands, and Google SDK paths cannot be covered by an assumed universal fetch wrapper. Apply these constraints through the real Pi entrypoint rather than an isolated adapter demo.

## Named acceptance cases and promotion evidence

These are proposed case IDs, not implemented test commands. Each fixture must fail if its corresponding admission, parsing or persistence behavior is removed. Deterministic fixtures establish faults; advertising a real profile additionally requires actual-provider/local-service opt-in evidence with pinned adapter/runtime/model/deployment, redacted request metadata, exact command/exit, receipts and observed limitations.

| Case                              | Required behavior                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `API_chat_tool_roundtrip`         | Loaded Pi turn receives split/interleaved Chat Completions tool arguments, executes one authorized synthetic local action and sends correctly paired results; final answer cites the resulting receipt. |
| `API_responses_sse_terminal`      | Reconstruct response item/call IDs and distinguish completed/failed/incomplete/error/EOF; no early completion or dispatch from unfinished arguments.                                                    |
| `API_responses_ws_reconnect`      | Optional WebSocket disconnect/continuation loss produces recorded failure or authorized reconstruction without duplicate local effects; SSE-only profiles remain usable.                                |
| `API_messages_block_usage`        | Indexed text/tool/thinking blocks, partial JSON and stream errors preserve order; cumulative usage is counted once and missing terminal usage remains unknown.                                          |
| `API_gemini_signature_roundtrip`  | Two-turn function/result exchange preserves applicable `generateContent` signatures; provider switch rejects or explicitly converts incompatible metadata. No inferred Interactions adapter.            |
| `API_cloud_identity_matrix`       | Independently test Azure deployment/resource auth, Vertex project/location identity and Bedrock region/profile/streaming model; denied identities make zero tool effects.                               |
| `API_native_ndjson`               | Optional native Ollama parser handles split UTF-8/lines, final done and broken streams; no SSE/NDJSON misclassification.                                                                                |
| `API_embed_rerank_contract`       | Optional operations reject wrong vector dimension/count/nonfinite values, undeclared truncation and missing/NaN scores; no mixed index generations or candidate-ID drift.                               |
| `API_retry_cancel_uncertain`      | Inject 429/5xx before output, disconnect after output/tool effect, cancel and release late data; retries/cost are explicit and uncertain effects never replay.                                          |
| `API_profile_egress_history`      | Mixed local/cloud role profile denies one data class, then resumes/switches models during streaming; current grants fence every real transport and history source.                                      |
| `API_barebones_adapter_lifecycle` | Fresh base starts without optional adapters/workers/assets; explicit add/disable/remove records dependencies, ownership and cleanup through interactive and headless paths.                             |

No provider gains another operation's qualification by sharing an API family. Experimental custom endpoints can pass compatibility/locality/egress/lifecycle probes without comparative quality benchmarks; recommendation/default promotion needs additional workload quality/resource evidence. Unrun cells remain **n=0**.
