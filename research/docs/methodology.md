# Research method and evidence boundary

Snapshot date: **2026-10-25**. Purpose: build a reusable evidence base for a later unified coding-agent CLI/harness, then derive one implementation plan. The current deliverable contains research and repository tooling, not a functioning harness.

## Scope and units

The scope covers coding CLIs, IDE agents, hosted agent platforms, reusable runtimes, workflow/spec scaffolds, retrieval/memory mechanisms, protocols, skills/plugins/hooks, execution substrates, observability, and evaluations. A model, protocol, benchmark, retrieval algorithm, and complete coding product are separate kinds of candidate. A successor/fork is separately identified when ownership or integration contracts differ.

“Every single tool” cannot be established for a changing, partially private ecosystem. Coverage is an explicit candidate register, source ledger, and query frontier. A scoped saturation result means repeated documented searches yielded no new eligible canonical identities; it does not prove that unknown/private/unindexed tools do not exist. Gaps in a known candidate's implementation, policy, license, or performance remain open even after discovery saturates.

## Chained rounds

| Round                     | Input                                         | Work                                                                            | Output                                                       |
| ------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1 — identity              | User-named candidates and ecosystem discovery | Resolve names, layers, forks, archives, and canonical sources                   | Terminal/IDE notes                                           |
| 2 — mechanisms            | Primary repositories and product docs         | Trace execution, context, permissions, extensibility and recovery contracts     | Framework, recursive, scaffold, protocol and retrieval notes |
| 3 — adjacent capabilities | Gaps from round 2 and user additions          | Follow retrieval, memory, hosting, optimization and tooling neighbors           | Extended internals and gap register                          |
| 4 — sparse retrieval      | Public papers and author repositories         | Examine sparse representations, order, approximate search and coordination      | Sparse-retrieval note with public provenance                 |
| 5 — closure               | All notes and outstanding candidate queues    | Deduplicate discoveries, resolve primary identity, repeat query-frontier sweeps | Dated sweep journal and explicit residual gaps               |
| 6 — synthesis             | Completed research and closure record         | Map mechanisms to owners, experiments and delivery phases                       | Proposed synthesis and root master plan                      |

At most three agents were active at once, including the coordinating agent, as requested. Independent lanes wrote separate files. That is a constraint of this research session, not a hard-coded product concurrency limit.

## Evidence classes

| Class                 | Meaning                                                                     | Permitted conclusion                                           |
| --------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Primary documentation | Official docs, upstream repository, original paper or author site retrieved | The linked source describes the stated mechanism               |
| Primary overview      | Identity plus a limited documented mechanism was confirmed                  | Candidate deserves qualification; details remain open          |
| Discovered only       | Name/attribution exists but selected primary evidence remains insufficient  | Put it in a queue; make no implementation or performance claim |
| Proposed              | Our design inference or recommendation                                      | Must pass the named acceptance experiment                      |
| Measured here         | Actual tests or remote settings verified in this task                       | Limited to the recorded command, revision, workload and result |

Source JSON records contain a stable local ID, candidate name, direct URL, title, access date, bounded claims, verification class, and notes. Some chapter citations include additional primary URLs beyond ledger records. A source-record count is neither a distinct-project count nor proof that all linked source code was audited. Moving branches/URLs require pinning before import, installation, adaptation or benchmark comparison.

## Comparison rules

1. Prefer primary sources; use search for discovery and selected-source retrieval for claims. Unavailable pages stay unavailable.
2. Label vendor/paper performance claims as reported. This task ran no coding-agent, model, retrieval or hardware benchmarks.
3. Compare mechanisms at the same layer. MCP support is not permission enforcement; worktrees are not sandboxes; checkpoints are not external-effect reconciliation.
4. Do not infer “unsupported” from silence. An undocumented capability is unknown.
5. Separate code existence, caller wiring, tested behavior, deployed behavior, and measured quality. A schema field or marketing table establishes none of the later stages.
6. Account for maintenance, API stability, license obligations, credentials, data retention, provider limitations, and evaluation contamination before adoption.
7. Prefer reuse when it passes the same tests. Feature count, stars, role counts, and leaderboard rank alone do not select a foundation.

## Refresh and closure

A future refresh reruns only stale identities or decision-relevant gaps, records changed sources, and updates the mechanism/acceptance mapping. New user requirements reopen the discovery frontier. Runtime qualification begins with pinned versions and actual conformance tests; documentary saturation never substitutes for those tests.
