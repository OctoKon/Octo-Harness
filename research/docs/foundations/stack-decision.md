# ADR-002: Rust-owned host with replaceable model services

## Status: Proposed

Research date: 2026-10-25. This refines [ADR-001](../design/synthesis.md) for Splyce. It is a stack recommendation, not a measured speed or quality result. No candidate was installed or benchmarked here (**n=0**).

## Context

Splyce needs one owner for CLI/headless runs, policy, action dispatch, receipts and memory across cloud and local models. The host supervises processes and persists effects; inference engines and language servers have different constraints and need not share its language.

## Approaches compared

| Approach                                                               | Benefit                                                                                                                                        | Key cost or fatal flaw                                                                                                                                                | Reversibility                                                                  |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Rust-owned host**, narrow adapters and external serving where useful | One compiled CLI, explicit ownership/lifetimes, mature async I/O, SQLite and text-index options; no Node/Python runtime required for the core. | More integration work and slower iteration; native dependencies, accelerator kernels and subprocesses still exist.                                                    | Two-way before journal/schema and plugin contracts ship; migration thereafter. |
| **TypeScript/Node host** with existing agent SDK                       | Fast path to provider/UI ecosystem and upstream code reuse.                                                                                    | JS process/runtime distribution and an additional native boundary for SQLite, parsers, isolation or local inference; policy interception must be proved, not assumed. | Two-way until sessions and plugins bind to its semantics.                      |
| **Python host** with established agent/inference packages              | Richest direct ML integration and short research cycle.                                                                                        | Packaging and process isolation across platforms become host obligations; Python's inference libraries do not themselves solve effect journaling or authority.        | Two-way before stored user state.                                              |
| **Fork or embed an existing harness** regardless of language           | Could remove most loop code.                                                                                                                   | Fatal if privileged actions cannot pass the host gate, or lifecycle/events cannot be journaled without invasive patches.                                              | Increasingly costly as upstream and local data diverge.                        |

**Decision:** prefer a **Rust-owned CLI, run host, policy gate, journal, memory owner and adapter contracts**. Rust is not universally fastest. Compare a minimal Rust slice with the shortest viable reused-harness slice on identical tasks, model, policy, recovery faults and runtime costs. Retain reuse if it proves every gate with materially less owned code. Tokio's async I/O fits supervision but offers no advantage for ordinary file reads [S01].

The user preference makes Rust the starting implementation choice; an exception needs a documented, evidence-backed decision. Language is a **two-way door** before persisted contracts. Journal schema, authority and deletion semantics become **one-way doors** for stored user data; require crash/deletion tests, migration rehearsal and security review. Rust costs more adapter work for an inspectable authority boundary. A universal plugin framework, graph database and embedded GPU engine would grow faster than demonstrated risk removal.

## Component choices and boundaries

| Owner                        | First candidate; alternatives and qualification                                                                                                                                                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI and event presentation   | `clap` for parsing; `ratatui`/Crossterm [S12] only if an interactive screen is needed. Headless events share the host.                                                                                                                                                |
| Async host and transport     | Tokio [S01]; `reqwest`/rustls, `serde`/`schemars`, `tracing`, optional OpenTelemetry. Keep blocking SQLite/index work off async workers. Test TLS, timeouts, cancellation and redaction.                                                                              |
| Journal and memory authority | SQLite via `rusqlite` [S04] for receipts, scopes, tombstones and metadata. Compare `sqlx` if async DB access removes a measured bottleneck. Journal is authoritative; indexes rebuildable.                                                                            |
| Search and code context      | `rg` first; Tantivy BM25 [S05] when corpus tests justify it. Tree-sitter uses a C11 core [S07]; LSP is an external process needing health/revision checks and lexical fallback. Neither grants edit authority.                                                        |
| Protocols and plugins        | Official MCP SDK `rmcp` [S02] stays behind policy. Start with process adapters; consider Wasmtime/WASI [S08] for third-party code. Test host grants and interruption; WASI does not sandbox native subprocesses.                                                      |
| Provider access              | Compare Rig's completion/embedding traits [S03] with `genai`/`async-openai` and narrow HTTP adapters. Rig's agent loop cannot become a second owner. Preserve tools, schema, usage, stop and cancellation semantics.                                                  |
| Local memory models          | `fastembed` provides embedding/reranking via ONNX Runtime by default [S06]. Evaluate sqlite-vec [S11] after BM25; compare Qdrant/LanceDB for larger concurrent corpora. Version vectors by model, dimension, normalization and instruction.                           |
| Generation engines           | Candle, Burn and `mistral.rs` need model/hardware qualification. Compare external vLLM [S09] and SGLang [S10] for accelerated serving; do not rebuild batching/KV scheduling. CUDA, C/C++, SQLite, ONNX Runtime and service dependencies make “pure Rust” inaccurate. |

The host exposes separate **generate**, **extract**, **embed** and **rerank** operations for local/cloud providers. Extraction requires schema validation and source evidence; embedding/reranking must not be inferred from generation support. Every adapter declares model/runtime revision, locality, limits, modalities, streaming/tool/schema behavior, cancellation, usage and error mapping. The egress gate acts per operation and data class. Local-only mode keeps raw receipts, derived indexes and every memory-model call local. Service failure leaves captured receipts intact and reports degraded retrieval.

## Contracts and proposed module map

`splyce-cli` parses commands and presents the event stream; `splyce-core` owns run state, stop reasons and capability negotiation; `splyce-policy` intersects grants and records decisions; `splyce-executor` supervises process/workspace effects; `splyce-store` owns journal, artifacts and migrations; `splyce-memory` owns capture, cited projections, deletion and retrieval; `splyce-provider` owns the four model-role contracts; `splyce-protocol` maps MCP/ACP without elevating authority. These are **module boundaries first**, not a demand for eight crates. Split crates only when independent compilation, unsafe/native linkage or stable public API warrants it.

An action carries run ID, unique action ID, workspace revision, target scope and validated arguments. The policy gate records a durable allow/deny/ask decision before dispatch; the executor rechecks scope at dispatch. An outcome receipt is durable before “complete.” Intent without outcome is **uncertain**, never automatically replayed. A memory projection carries source receipt IDs, scope and index generation; deletion invalidates every projection and cache. A provider result includes exact backend/model revision, observed usage and stop/error reason. External service/process adapters declare which internal effects they cannot observe and cannot claim stronger audit guarantees.

Qualification gates: (1) deny and cancellation survive MCP, delegation, resume and adapter failure with no denied effect; (2) kill between every intent/side-effect/outcome boundary, reconcile unknown effects and prevent duplicate external writes; (3) deleted or cross-workspace material cannot surface from SQLite, BM25, vector, summary, export or cache; (4) LSP crash/stale revision falls back or fails visibly; (5) paired Rust/reuse/TS/Python spikes use the same pinned task set, model, permissions and hardware, reporting task success, p95 latency, startup, peak memory, binary/install footprint and maintenance diff separately. No winner is asserted before these measurements. Before dependency adoption, pin versions and record upstream license, transitive/native licenses, security/update cadence and redistribution terms.

## Consequences

- **Positive:** one host can make authorization, receipts and memory consistent across interfaces and model backends; inference remains replaceable by hardware and workload.
- **Negative:** provider semantic mapping, blocking/native library management and cross-platform packaging are real Rust-host costs.
- **Risks:** an opaque backend can hide effects; native plugins can bypass WASI limits; SQLite/index divergence can leak deleted data; an LSP can return stale ranges; an inference service may expose unguarded endpoints. The gates above, versioned adapters and explicit capability labels contain these risks but do not yet prove safety.
