## Reusable mechanisms for a Pi-first engine

The selected product direction is to extend an existing Pi-based engine, not to create a new runtime. The useful boundary is therefore a thin, explicit adapter around Pi's observed request, tool, result, approval, cancellation, and session surfaces. Do not place a second autonomous loop inside that adapter.

### Context continuity: Prometheus and SpecRover

Prometheus separates durable codebase representation from working memory for long-horizon navigation. SpecRover makes inferred intent and a reviewer judgment explicit. Reuse the narrow idea: store versioned navigation/retrieval receipts and pass a bounded intent/verification artifact into the Pi turn. Do not import either agent loop or accept their paper-reported scores as selection evidence. Qualification: on a fixed repository, prove that each retrieved item is traceable to a revision and that a stale artifact is rejected after a conflicting edit.

### Branching and recovery: DARS-Agent

DARS makes search branching a first-class concern rather than silently retrying a single trajectory. In a Pi-first design, retain only bounded alternative proposals with explicit budgets and disposable workspaces; Pi remains the only model-turn owner. The selected source does not establish safe replay, idempotent effects, or the canonical upstream implementation. Qualification: inject a failed branch and prove its worktree, commands, and artifacts cannot alter the accepted branch.

### Specialized work and checkpoints: SWE-AF

SWE-AF's useful pattern is a DAG of distinct artifacts and roles: plan, issue, code/test, review, merge, and verification. A Pi-first engine can represent those as task records and invoke Pi with a scoped role prompt, but should not inherit unrestricted remote-agent, credential, or PR authority. Qualification: block a failed verification receipt from advancing state and prove the resume path does not duplicate an already-recorded external operation.

### Execution isolation: SWE-ReX

SWE-ReX demonstrates a useful distinction between an agent and a shell-environment adapter. For Pi, the executor adapter should expose only a declared command/session contract and emit ordered receipts. The selected README supports backend portability, not an operating-system security guarantee or exactly-once semantics. Qualification: cancel a long-running command, wait for process teardown, and verify no later tool turn can reuse its session or observe unredacted output.

### Configuration generation: rulesync and agent-scaffold

Rulesync centralizes source material then generates target-specific agent configuration; agent-scaffold provides a repeatable project starting point. Both are preparation tools. Reuse only pinned, reviewable input artifacts and a preview/diff gate before generated files are applied. Treat generated rules, MCP declarations, hooks, and permissions as untrusted changes that need the same approval path as hand-edited configuration. Qualification: a forbidden permission or remote endpoint in a source artifact must fail the preview gate and leave the workspace unchanged.

### Process guidance: vibe-coding-toolkit

The toolkit's portable prompts, templates, and quality-gate guidance can seed human-reviewable project artifacts. They must not become implicit runtime authority or override project policy. Qualification: an imported prompt may propose a task, but it cannot bypass Pi's tool approval or alter the approved command allowlist.

## Source and evaluation limits

Prometheus and SpecRover are research papers; DARS-Agent's selected repository has an explicit fork lineage; the other sources are moving repositories. Pin a commit, release, or paper version before an implementation spike. None of the sources establishes compatibility with Pi, Rust support, a sandbox boundary, provider parity, benchmark transfer, or production reliability.

The next useful experiment is a small disposable-repository Pi adapter with durable artifact receipts, previewed configuration generation, cancellation teardown, and a fixed task budget. Compare it against bare Pi on the same tasks; report task outcomes, input/output tokens, latency, failures, and recovery behavior without claiming a benchmark result from one run.
