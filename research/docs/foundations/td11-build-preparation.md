## Runtime decision to carry into the bootstrap

Keep the [locked Node 24 selection](desktop-stack-decision.md) for the first build candidate. The [release schedule](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json) puts 24 in maintenance from 2026-10-20 through its 2028-04-30 end of life; 26 enters LTS on 2026-10-28 and ends support on 2029-04-30. On this access date, 26 is therefore a comparison candidate, not the selected LTS runtime. Recheck the schedule when freezing the actual build rather than copying the release table's potentially stale status label.

The [October security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) supplies fixes in 24.22.1 and 26.12.1. Treat these as dated minimum security inputs, not a claim that either is the latest patch. The existing MXC compatibility floor in the stack contract (24.21.0 or 26.8.0 for Windows stdio transfer) does not lower that security floor. Recheck all advisories at the actual freeze. The Pi donor's declared Node range is not proof that its full native/optional closure works on either major.

The upgrade drill must build each candidate from the same fork revision and selected closure, run actual engine/GUI/readiness/native-denial and shutdown tests, and record runtime bytes and results per architecture. Exercise existing-state reopen and recovery before switching the packaged runtime; preserve a rollback path without dropping user data. No result is available for either candidate here.

## Serial handoff

TD-01 owns the shared records and initial contract runner. TD-07 owns the core/Rust/process boundary. TD-11 takes root scripts and runner configuration only after that handoff, using the declared joint bootstrap branch. TD-08 later takes over the readiness-only renderer skeleton. This preparation changes none of those paths and makes no durable-admission claim.

At bootstrap freeze, record the selected runtime major/patch/end-of-life, exact toolchain and source pins, support cells, selected payload closure, artifact hashes, and upgrade/recovery evidence. Add every introduced engine/GUI runner to the release gate. Unsupported or unrun mandatory cells remain blockers, never inferred passes.
