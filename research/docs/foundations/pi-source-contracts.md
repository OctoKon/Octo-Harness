# Pi source contracts for a Splyce integration

**Public source audit, 2026-10-25.** This is a reading of `earendil-works/pi` at commit `d5b3de22d0e24a3e9c38a9410d3329b099717283` (`@earendil-works/pi-coding-agent` 1.4.0, MIT, Node >=22.19.0), not an installed-runtime qualification. Links resolve to pinned source lines; [PS-01–PS-11](../evidence/pi-source-sources.json) record the primary sources. “Observed” below means the source implements the described control flow. “Enforce” is a proposed Splyce obligation, not a claim that Pi provides the policy. No exactly-once effects, sandbox, or universal approval guarantee follows from these hooks.

**Current adoption boundary, 2026-10-26:** these source observations retain their upstream pin. Splyce uses the [owned native core](../design/core-fusion.md); source hooks are donor/control-flow and optional-resource surfaces, not an extension-only authority implementation. Run every enforcement fixture through actual core/SDK/RPC and GUI callers; no successful hook-only test qualifies native dispatch or persistence.

## Construction and request path

**Observed:** [`createAgentSession`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/sdk.ts#L191-L212) resolves cwd, model runtime, settings, session manager and a resource loader, reloads default resources, then reads the existing branch/context. It selects restored/default model and tools before building an `Agent` whose stream function calls `modelRuntime.streamSimple`, context passes through extension transformation, and tool hooks are installed on the session. It returns `{session, extensionsResult, modelFallbackMessage}`; extension events begin when the mode/SDK caller binds extensions, not merely when the object is constructed. [SDK lines 403–479](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/sdk.ts#L403-L479), [bind lines 3320–3342](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/agent-session.ts#L3320-L3342).

**Enforce/test:** Supply a pinned resource loader/session manager and establish native policy/store readiness before the first prompt; selected extensions cannot substitute for that readiness. Fixture `sdk-bind-order`: custom resource plus registered tool is visible to first prompt; missing model returns fallback and no unapproved action executes. Negative: constructing a session without binding cannot be treated as a policy-ready session. `tools`/`noTools` selection affects model visibility, not a security boundary; [SDK lines 280–294](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/sdk.ts#L280-L294).

## Tool decision, failure and result projection

**Observed:** `AgentSession` wires `beforeToolCall` and `afterToolCall` into the Agent. Before execution, `tool_call` carries name, ID, input and optional parent ID. [`emitToolCall`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L1249-L1267) runs handlers in order and returns at first `{block:true}`. A thrown pre-call handler propagates, so the call cannot proceed on that path; this is source control flow, still requiring a runtime test. [Session lines 644–681](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/agent-session.ts#L644-L681), [result type](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/types.ts#L1454-L1463).

**Observed:** After execution, `tool_result` can replace `content`, `details`, `structuredContent`, `isError` and `usage`. Replacing `content` without `structuredContent` drops the latter. A throwing result handler is reported and skipped, then later handlers continue: redaction implemented _only_ there is therefore not fail-closed. [Runner lines 1190–1246](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L1190-L1246), [session projection lines 683–723](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/agent-session.ts#L683-L723).

**Enforce/test:** Put the grant decision before the call and record attempted/denied outcomes independently of transcript content. If an awaited pre-effect receipt write rejects, block actual native executor entry; the upstream `tool_call` throw path is one donor observation, not the sole enforcement route. This only establishes local order. Pi's session file and a separate Splyce store cannot be committed atomically through this API: a crash or network loss can leave an uncertain join. F0 must prove receipt persistence acknowledgment precedes executor entry, failure blocks execution, and restart reconciles a Pi call with a missing/uncertain Splyce outcome. Fixture `deny-before-effect`: blocked or thrown pre-call policy reaches neither executor nor MCP server. Fixture `result-failure`: a result handler throws while sensitive synthetic content exists; Splyce's output boundary withholds `content`, `details`, `structuredContent` and exported/JSON surfaces or marks the operation failed. Do not assume a `tool_result` hook by itself redacts durable session files or extension error logs. Those paths remain **untested**.

## Nested calls and receipts

**Observed:** [`ExtensionToolContext.executeTool`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L964-L995) forwards the parent ID and signal. `AgentSession._executeNestedToolCall` runs the chosen tool through the same before/after hooks and emits nested execution events. IDs are `<parent>/<n>`; nested calls appear as a bounded `nestedCalls` summary on the parent's result, not as independent transcript tool messages. The summary can omit arguments or calls and set `complete:false`; upstream tests exercise parent IDs and limits. [Session lines 726–764](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/agent-session.ts#L726-L764), [record limits](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/nested-tool-calls.ts#L21-L100), [tests](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/test/nested-tool-calls.test.ts#L54-L100).

**Enforce/test:** Correlate every nested attempt at hook time into Splyce receipts; do not reconstruct the effect ledger from bounded `nestedCalls`. Fixture `nested-deny`: a permitted parent requests a denied child and the child executor is never invoked. Negative: >256 child calls or oversized arguments produce an incomplete transcript summary while operational receipts still reflect every attempted call.

## Branch state and compaction

**Observed:** [`appendCustomEntry`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L118-L131) persists extension data as a child of the current leaf; it is ignored by LLM context. [`getBranch`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1464-L1486) walks leaf to root. [`buildContextEntries`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L469-L512) selects that path, newest compaction entry and retained tail. Compaction constructs a model-facing summary/projection, not a durable action journal. [Custom append](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1289-L1301), [compaction preparation](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/compaction/compaction.ts#L769-L880).

**Enforce/test:** Rebuild extension state from the active branch, with receipts kept independently and keyed by branch and action ID. Fixture `fork-compaction`: write custom state on branch A, fork before it, compact B, reload; B cannot present A's abandoned action as completed. Negative: a dropped summary detail must not erase its original receipt or turn uncertainty into success. Persistence/fsync and crash recovery remain **untested**.

**Identity mapping:** Pi exposes `getSessionId()`, `getLeafId()` and `getBranch()`; this source has no `branchId` API or persisted branch identifier. `branch(entryId)` changes the leaf pointer within the same session; a subsequent append makes a child. `newSession()` creates a new session ID and null leaf. `forkFrom()` makes a new session ID/header with `parentSession` and copied history. [Identity getters](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1152-L1154), [leaf getter](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1404-L1406), [branch mutation](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1573-L1584), [new session](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1057-L1082), [fork](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/session-manager.ts#L1815-L1855). Splyce may define its own `branchAnchor` as `{piSessionId, forkPointEntryId, firstChildEntryId}`; before the first child, use `{piSessionId, forkPointEntryId, firstChildEntryId:null}`. `piBranchId` would be a **Splyce-derived field**, never an upstream Pi value. Test navigation among sibling children with the same session ID, plus a file fork with a new session ID.

## Lifecycle and cancellation

**Observed:** Binding emits `session_start` then resource discovery. Reload emits `session_shutdown` on the old runner, invalidates it, reloads settings/resources, builds a new runtime, and emits `session_start` when bindings exist. Event reasons include startup/reload/new/resume/fork and quit/reload/new/resume/fork. [Event types](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/types.ts#L754-L829), [reload](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/agent-session.ts#L3720-L3759). Print/JSON mode disposes its runtime in `finally` and on termination signals, but hard process death cannot run callbacks. [Print mode](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/modes/print-mode.ts#L42-L68).

**Enforce/test:** Make Splyce-owned cleanup idempotent and reconcile incomplete actions at next start. Fixture `reload-inflight`: cancel a synthetic operation during reload, release owned resource once, reject stale context, and restart with a new resource. Negative: kill the process after an external effect but before result persistence; receipt status must be uncertain, never automatically replayed or asserted complete.

## MCP and provider seams

**Observed:** Built-in MCP reads configured and extension-registered servers on `session_start`; background connection discovers tools via `listTools`, then registers Pi tools. A configuration server wins a same-name conflict. Exposure may be codemode, deferred, direct or hidden. The pre-call readiness handler waits for relevant servers; the execution closure rechecks server enablement and tool availability. [MCP start](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/extensions/mcp/index.ts#L1114-L1137), [discovery](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/extensions/mcp/runtime.ts#L359-L397), [registration/recheck](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/extensions/mcp/index.ts#L387-L445), [readiness](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/extensions/mcp/index.ts#L1186-L1209). Connection errors surface through state; read-only HTTP requests may retry, while ordinary tool calls are not retried on transient HTTP errors because effects may have occurred. [Runtime lines 274–300](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/extensions/mcp/runtime.ts#L274-L300).

**Observed (codemode and temp outputs):** `codemode` is the default MCP exposure and activates when such a server connects. Its QuickJS scripts reach tools and a `models` global that runs classifier and image models with the session's credentials through `KnownClassifierApi`/`KnownImageApi`, outside the ten chat `KnownApi` families; `store()` appends `codemode-store` session entries. Pi also writes truncated MCP text, long bash output (`full_output_path`), codemode images and binary MCP resources to temporary files. An installed extension registering `/mcp` replaces built-in MCP. [Codemode](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/docs/codemode.md), [MCP exposure and SDK](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/docs/mcp.md), [API types](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/ai/src/types.ts#L64-L90).

**Enforce/test:** codemode-originated tool calls, `models` calls and `store()` writes are separate admission, egress and redaction routes (TD-04/13/50); temp outputs join the TD-79 retained-copy inventory under an owned temp root.

**Enforce/test:** Apply grants to the resolved MCP tool at actual call time, including indirect calls. Fixture `mcp-late-tool`: server advertises a tool after first prompt; it remains denied until granted. Negative: disconnect during an effect yields uncertain outcome and no blind retry. MCP registration/discovery is **source-observed**, not tested against a server here.

**Dispatch boundary:** MCP tools registered through `pi.registerTool` use the ordinary tool pipeline, including the nested `ctx.executeTool` path. The interactive user's shell command is a different path: `handleBashCommand` emits `user_bash` before local execution, and the runner rethrows handler errors; it does not pass through `tool_call`. [Interactive command](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L6983-L6997), [runner](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L1269-L1297). Enforce that path separately, with fixture `user-shell-deny`: a rejected receipt write or denial prevents local execution. Other direct extension/OS effects outside Pi tools remain outside these hooks and need a constrained executor or trusted-code scope.

**Observed:** Extensions can register providers. `ProviderConfig.streamSimple` receives normalized transcript context and must invoke payload/response callbacks; the SDK routes through `modelRuntime.streamSimple` and forwards provider events. [Types lines 1934–1958](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/types.ts#L1934-L1958), [SDK lines 374–427](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/sdk.ts#L374-L427). **Inference:** A third-party custom adapter can violate those callback instructions; registration is not proof of transport observability.

**Enforce/test:** Pin provider identity and route secrets through the configured credential facility. Fixture `provider-callbacks`: custom adapter invokes payload/response hooks in order, with status and model recorded; negative adapter omits one callback and qualification fails.

## Headless parity boundary

**Observed:** `print`/`json` bind extensions and submit prompts, while absent UI uses no-op `select`/`input`, `confirm:false` and `notify` with no display; `hasUI` is false for that context. [Print mode lines 74–132](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/modes/print-mode.ts#L74-L132), [runner UI lines 331–350](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L331-L350), [`hasUI`](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L624-L630). RPC may supply a UI context; “headless” alone does not define approval behavior.

**Enforce/test:** Require an explicit noninteractive approval channel or deny an action that needs user approval. Fixture `headless-approval`: run the same proposed operation in interactive and print/JSON modes; with no approval source, both deny and record the decision. Negative: `ctx.ui.confirm()` returning false must never be interpreted as an implicit grant. No mode parity or full integration run was executed for this audit.
