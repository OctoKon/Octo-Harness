# Lightweight local runtime comparators

Research date: 2026-10-25. Evidence: [lightweight-runtime sources](../evidence/lightweight-runtime-sources.json). Splyce keeps execution, memory, and state local. Each inference role uses a recorded local runtime or explicitly authorized cloud API profile; cloud egress is per-role and never a fallback. This chapter examines seven canonical projects as donor/base comparators. It does not rank popularity, repeat the separate HKUDS/nanobot gap record, or assert installation, binary size, RSS, model-server cost, latency, security, or correctness. Every runtime claim below is source-backed only; measured result: **n=0**.

Pi at `d5b3de22d0e24a3e9c38a9410d3329b099717283` remains the active starting base because it supplies the selected TypeScript/Node coding loop, extension seams, session/branch handling, interactive/headless modes, and built-in MCP [LR-13]. The comparison is bounded: an existing local implementation may provide a reusable donor or replace Pi only by passing the _same_ F0, lifecycle, local-only, coding-verifier, recovery, memory, and resource contract. A Rust or Go implementation alone is neither a speed result nor authority to port Pi or create a new loop.

## Selection boundary

The selected sources are canonical repositories with an inspectable README plus a pinned manifest and license signal. ZeroClaw, IronSecCo/IronClaw, nearai/IronClaw, PicoClaw, NanoClaw, Moltis, and OpenCrabs cover the named frontier without treating messaging daemons as coding CLIs. The two IronClaw projects are distinct namesakes: IronSecCo is the Go alpha under AGPL/commercial terms, while nearai is a Rust Agent OS under MIT OR Apache-2.0. `Moltis`, `OpenCrabs`, and nearai/IronClaw are useful counterexamples: a single binary or local-provider option can still have a large feature and dependency surface. `PicoClaw` explicitly labels early rapid development. `NanoClaw` is container/messaging-led and its setup installs external local infrastructure. These are capability and lifecycle differences, not defects.

## Non-negotiable comparison gates

| Gate                  | Required proof in the same disposable coding fixture                                                                                                            | Fail condition                                                                        |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Exact role profile    | One pinned local runtime/model or explicitly authorized cloud API profile per enabled role; no compatibility assumption from an OpenAI-shaped endpoint          | A role silently calls an unrecorded endpoint or cannot identify its model/runtime.    |
| Offline / zero egress | Network deny at host/executor boundary from launch through shutdown; DNS, provider discovery, telemetry, update checks, web tools, and model fallbacks included | Any undeclared outbound connection or attempted fallback.                             |
| Coding verifier       | A permitted edit reaches a real local test/formatter against the final revision and records command/exit/diff                                                   | A chat, demo, unit mock, or stale verifier receipt is reported as coding completion.  |
| F0 authority          | Ordinary tool, nested tool, built-in MCP, extension/hook, and explicitly separate `user_bash` route cannot bypass a denied capability                           | A denial produces any effect or an unobservable path is called controlled.            |
| Lifecycle             | Start, cancel, timeout, terminal disconnect, restart, and repeated shutdown leave no owned process/container/resource or record an explicit survivor            | “Stopped” is inferred from UI state rather than process/executor observation.         |
| Recovery              | Crash between decision, durable intent, dispatch and outcome produces uncertain state; physical target is reconciled before retry                               | Intent without outcome is replayed or called success.                                 |
| Memory                | Scope-before-retrieval, cited source recovery, correction, deletion from raw/index/cache/backup, restart and branch isolation                                   | A summary or index result without source evidence is treated as authoritative memory. |
| Toggle / profile      | Local-only, coding-CLI, messaging disabled, browser disabled, remote disabled, and MCP profile states are explicit, auditable, and restart-stable               | An optional channel/provider/tool remains reachable when its profile says disabled.   |
| Resource              | Measure pinned runtime, local model server/weights, optional assets, executor, idle and task peak on each advertised platform                                   | A standalone agent-binary figure is used as full-stack cost.                          |

The F0 fixture uses the pinned Pi baseline and every comparator with identical task, model revision, local workspace, network denial, user grant, and resource collection. It executes a permitted edit and final verifier; denied direct/nested/MCP actions; user shell separation; interruption at effect boundaries; branch/session reload; empty-context cited recovery; deletion; and cleanup. A comparator that lacks a documented seam may still be viable, but only if it proves equivalent observed behavior without a hidden second authority.

## Reuse matrix

| Concern                 | Pi-first reuse                                               | Comparator lesson                                                                         | Splyce rule                                                                                            |
| ----------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Model loop and sessions | Retain Pi's loop, branch/session semantics and headless path | Messaging daemon session isolation does not equal coding-session recovery                 | No new loop and no Rust/Go port.                                                                       |
| Model profiles          | Pi provider contract plus explicit endpoints                 | Candidates may advertise local providers alongside hosted fallbacks                       | Local-only is one pinned deny-egress profile; cloud roles need explicit endpoint/model/egress records. |
| Tool/process isolation  | Splyce executor boundary                                     | IronClaw/NanoClaw/Moltis demonstrate that sandboxing is a separate executor choice        | Treat in-process extension code as trusted; qualify container/VM/WASM boundaries independently.        |
| Memory                  | Splyce evidence/receipt contract                             | SQLite or “persistent memory” does not demonstrate scope/deletion/recovery                | Preserve source IDs, deletion tombstones and rebuildable projections.                                  |
| Terminal/coding         | Pi TUI/RPC/JSON plus owned command adapter                   | PTY/channel capability is not a coding-verifier contract                                  | Final revision and local verifier receipt define completion.                                           |
| Resource reduction      | Feature-minimal Pi package first                             | Rust/Go packaging may lower deployment overhead but has unmeasured selected-feature costs | Start optional workers only when measured need exceeds idle cost.                                      |

## Selection receipt

**Current result:** retain Pi as the starting base, with a minimal TypeScript extension/package and a separately qualified local executor. Evaluate selected comparators only as bounded donors or as a controlled replacement experiment. The experiment may replace Pi only if it passes every gate above and demonstrates a consequential capability, maintenance, or lifecycle advantage; it must then record source pin, license, exact profile, commands, artifacts, resource results, failures, and final decision. Cloud inference does not authorize a managed executor or hosted memory. A candidate failing one hard gate is not patched around by adding a second agent loop.

This conclusion is deliberately narrower than “Pi is fastest” or “Rust/Go is lighter.” No such measurement exists. The immediate engineering preference is the smallest local Pi extension that enforces receipts and profiles; portable Rust/Go executor support needs an observed capability gap that Node/Pi cannot satisfy.

Skipped: no candidate was installed, benchmarked, or security-audited. Risk: source claims and moving projects may differ from pinned runtime behavior; all performance and local-only claims remain n=0.
