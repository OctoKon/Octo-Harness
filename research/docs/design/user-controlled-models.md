# User-controlled models

**Status: proposed, unimplemented; runtime and model-quality results n=0.** This records the user's model-choice requirement and narrows [C4/R1 in the master plan](../../../MASTER-PLAN.md), the [capability map](capability-map.md) and [provider contracts](implementation-contracts.md). It defines product behavior, not a new inference engine or model registry service.

The [barebones install](modular-installation.md) contains no optional module/model payloads. Users choose the model for each installed/enabled operation: installed local weights/services or explicitly selected hosted providers. No fixed brand allowlist, required model subscription or silent fallback. [Profiles/session contracts](providers-profiles-and-sessions.md) own multiple providers, API families, data-class egress, cloud credentials and live changes. Compatibility depends on actual runtime/model/API/operation; unsupported formats or protocols report the missing adapter rather than substitute a model. A forecasting checkpoint cannot serve chat merely because its files load.

## Selection and ownership map

Reuse Pi's observed generation/provider selection; Splyce adds only the missing operation binding, local admission and lifecycle evidence. The entries below are proposed fields/behaviors, not existing Pi APIs, a complete configuration schema or implemented commands.

| User-controlled item   | Required behavior / owner                                                                                                                                                                                                                                                                                                   | Decisive test                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Operation binding      | Choose generation, extraction/summary, embeddings and reranking independently. Optional decision, forecast, OCR/vision/audio and speculative-draft paths declare their own typed capabilities; they do not silently enlarge the core four-operation enum or require extra models when a compatible shared service suffices. | One compatible model per operation; generation-only service rejects embedding/forecast calls before dispatch.          |
| Model selection        | Exact checkpoint/revision or local content digest, tokenizer/template/config, quantization/adapters and runtime revision form the model contract. No silent latest-version update.                                                                                                                                          | Local custom checkpoint absent from a curated catalog can pass compatibility probes and be selected.                   |
| Asset source           | Explicit local file/directory import or user-requested pinned download with source, sizes/digests and license reference. Download permission is separate from inference, and installation never enables a feature.                                                                                                          | Cold offline run uses declared installed assets only; enabling a feature attempts no download.                         |
| Runtime/service        | Identify an owned local worker or a user-managed local service or explicit hosted provider and actual served model. Enforce the selected profile's endpoint/data policy and reject unqualified redirects; an OpenAI-shaped API or loopback address alone proves neither locality nor capabilities.                          | Service identity changes or redirects fail admission; all roles follow their separately declared local/cloud policies. |
| Residency and sharing  | Enabled means eligible, not always resident. Users may share one compatible local model across roles or choose separate models; track owned references and resource use.                                                                                                                                                    | Disable one role without unloading another active role's shared model; leave externally owned service running.         |
| Switching and rollback | Commit a new selection revision atomically; new work uses it. Keep existing jobs bound to their old contract until explicit drain/cancel/retry disposition; no mixed-contract publication.                                                                                                                                  | Switch while embedding/summary/forecast work is paused; stale output cannot enter the newly selected generation/cache. |
| Removal                | Disabling retains weights. Explicit uninstall deletes only owned selected assets after reporting references; local import does not transfer ownership of the user's original files.                                                                                                                                         | Uninstall an imported selection preserves its external source and blocks affected bindings honestly.                   |

The same checkpoint may qualify for several roles, but each role gets its own shape/limits probe. Summary can reuse the generation service only when extraction/citation validation qualifies. A specialized forecast adapter validates series, time availability, units, horizon and quantiles; a decision adapter validates candidate identities, probabilities and abstention. See [decision models](../capabilities/decision-models.md) and [forecasting](../capabilities/forecasting-models.md).

## Product support and user experimentation

Keep three independent facts visible: **user selected**, **compatible for this operation**, and **qualified/recommended for this platform/workload**. Do not call a merely loadable checkpoint supported, or prevent an explicit experimental selection solely because it lacks a comparative Splyce benchmark. Experimental selections must still pass actual locality/authorized egress, argument/output, authority, cancellation and lifecycle checks for the operation; model output never grants permission or certifies completion. Inconclusive quality is recorded as unmeasured, not hidden behind a default model replacement. Failed operations retain evidence and report their cause.

Splyce's code and distributed dependency set remain OSS. Bundled/downloaded-by-default assets require redistribution rights compatible with the published product; notices and actual code/weight/tokenizer/conversion terms are separate. Users may independently provide other local weights, a separately installed runtime or a hosted model connection when their terms permit their intended use. Such a selection does not relicense those assets, make them unrestricted OSS, include them in Splyce's distributable, or establish a supported profile. License records expose the upstream terms without pretending Splyce can infer the user's legal eligibility from a model name.

**Timestral example:** a permitted user can explicitly install/select a compatible local Timestral forecast checkpoint. The inspected [28M weights license](https://huggingface.co/mistralai/Timestral-28M/blob/49b26409ac87b5935539a5d8ffe7f397b720db47/LICENSE) has a company/employer revenue restriction; the [source-backed review](../capabilities/forecasting-models.md#chain-1-identify-official-timestral-then-separate-code-and-weights-rights) explains it. Therefore these weights cannot be advertised as an unrestricted OSS default. That restriction is not a blanket product ban on eligible users bringing their own checkpoint. Other models/sizes need their own actual-file review and compatible adapter; no brand-specific exception is needed.

An imported model card/config is data, not installation authority. Never execute fetched Python, package hooks, pickle payloads or adapter code merely because a checkpoint requests it. If a model requires custom code, report that dependency; any separately installed, reviewed local adapter uses the existing trusted-extension/executor boundary and explicit permissions. No second agent loop or unrestricted model-loader escape is created.

## Migration, deletion and reproducible tests

Every job/receipt binds its selection revision and complete model contract. A Pi streamed/tool-bearing turn finishes under its original binding or is canceled with its outcome recorded before the next turn uses the replacement; never splice two models into one falsely attributed turn; changing to a cloud provider revalidates prior-context egress before sending it. Embedding changes isolate index generations even when vector dimensions match; tokenizer, normalization, metric, instructions and truncation changes count too. Retain the original source and old generation until a user-authorized rebuild validates and atomically cuts over. Do not query mixed vector spaces. Extraction/summary changes preserve provenance and versions rather than overwriting observations. Scope/deletion epochs fence all late outputs and serving caches, including model-switch races. If an external service cannot meet required purge/isolation behavior, the affected profile stays unavailable for that data class.

| Proposed fixture / package             | Required observation                                                                                                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `C4_custom_cloud_selection` / C4       | Compatible custom hosted endpoint/model outside a curated list is selectable only under the explicit role/profile/data grant; all-local profile denies it with zero dispatch.                                                                            |
| `C4_custom_local_selection` / C4       | Two synthetic compatible local identities not in a curated model list can be selected independently; real checkpoint support additionally requires actual-model evidence.                                                                                |
| `C4_wrong_operation` / C4              | Generation-only endpoint and chat adapter cannot accept embed/forecast input; failed probe leaves previous binding intact with no silent substitution.                                                                                                   |
| `C4_model_switch_fence` / C4, M1–M2    | Same-dimension embedding swap and streamed/tool-bearing generation swap cannot mix contracts, silently replay an effect, reuse incompatible vectors or falsely label a result with the new revision.                                                     |
| `C4_provision_offline` / C4, R1        | Import/preparation is explicit; rejected/incomplete download leaves no active binding; all-local installed offline/missing-role cases make zero hosted attempts; a cloud profile reports its connectivity requirement without silent local substitution. |
| `C4_custom_code_boundary` / C4, P1     | A checkpoint requesting executable loader code causes no execution or new grant during discovery/import/probing.                                                                                                                                         |
| `C4_shared_service_ownership` / C4, R1 | Disable/uninstall releases only owned references/assets; another role and the user's external service/source files survive.                                                                                                                              |
| `R1_selection_roundtrip` / R1          | Interactive and headless selection, inspect, restart, disable and export preserve exact identity, ownership, support state and scoped local configuration.                                                                                               |

Contract-fault fixtures use synthetic models/services. Actual format/device claims need installed-model tests; recommendation or improvement claims additionally need frozen paired quality/resource trials. These cases are not runnable scripts yet. Owners implement them through Pi's real loaded user path, recording revision, commands, artifacts, outputs, failures and unrun limits in the [qualification register](qualification-register.md).
