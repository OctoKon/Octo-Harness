# Research and build-readiness audit

**Active product scope:** Splyce is OSS with a barebones, modular local application and local authoritative state. Users explicitly select local and/or cloud inference per provider/profile/operation; a local-only profile forbids inference egress and silent fallback. Hosted execution, managed memory storage and unsolicited telemetry are not default dependencies. Current local+cloud direction supersedes the earlier global local-only ruling. [Current master plan](../../../MASTER-PLAN.md).

Audit date: **2026-10-25**. This is a traceability audit, not a runtime acceptance or a claim that every internet project has been discovered. All product qualification remains **n=0**. The [master plan](../../../MASTER-PLAN.md) is the active build authority; [implementation contracts](implementation-contracts.md) define proposed records and invariants.

## Current provider/profile/session amendment

The latest user ruling permits local/cloud inference with explicit per-operation profile/endpoint/data grants; it supersedes the earlier global local-only product rule. [Workflow contracts](providers-profiles-and-sessions.md) map multiple providers, versioned profiles, live switching, resume/fork, multi-client ownership, export/import and protocol conformance. Local-only profiles keep zero model egress. Optional cloud SDKs remain selected dependencies; hosted executor/memory storage is not implicitly enabled.

## Barebones installation amendment

The default host installs no optional memory/RAG/LSP/skill/server/model payloads. [I1/R1 module contracts](modular-installation.md) govern explicit Git-pinned selected dependency closure, setup/skip/add/update/remove, loader isolation and retained-data cleanup. Optional module gates are conditional support cells; M1/M2/X1/P1 are not prerequisites to shipping the barebones core. Zero unselected installed bytes/imports/fetches must be observed, not inferred from disabled controls.

## User model-choice amendment

[Model-choice contracts](user-controlled-models.md) separate per-operation custom local and hosted selection, experimental compatibility and product recommendation. Permitted independently supplied Timestral/other assets need not enter the OSS distributable. C4/R1 require explicit provisioning, endpoint/data-class policy, credential/checkpoint/code boundaries, selection/index/stream fencing, provider cancellation/retention, service ownership, resume and all-local/offline fixtures before this user path exists; comparative model quality remains unmeasured.

## Hard gates that remain open

1. **F0 authority seam:** Pi's tool and user-shell hooks must block denied effects at actual dispatch. Direct OS operations in trusted extensions are outside tool-hook containment.
2. **Output boundary:** a throwing result hook can be skipped by the inspected runner. Redaction must cover actual persistence, updates, structured content, errors, headless/export and provider surfaces. Implement this on the native Pi-derived publication/persistence path identified in the core-fusion patch map; an outer result wrapper cannot establish coverage.
3. **Durability and ancestry:** separate Pi/session and operational stores require explicit joins/reconciliation. Splyce branch anchors map real entry ancestry; no fictional upstream branch ID.
4. **Memory backend/runtime:** OMP's inspected Mnemopi code uses Bun SQLite and workspace-native dependencies. Node compatibility is not established. Compare total reuse/port/service cost against a simpler qualified store.
5. **Deployment/release:** advertised local models and OS/device combinations need actual installed end-to-end evidence. Development fakes establish faults, not model quality or real containment.
6. **Imported provenance:** unresolved identities and numerical claims remain explicitly unverified. Do not make them architecture constants or benchmark results.

## Specification review amendments

Independent review identified four missing constraints now carried by the master/contracts: immutable workspace snapshots beyond Git HEAD; deletion epochs that fence late producers and surviving Pi/model copies; J0 storage before durable policy admission; and bounded alternative-base comparisons even if Pi passes a hard gate. These are specification repairs, not observed runtime fixes. The corresponding negative fixtures remain mandatory and unrun.

## Research completion rule

Close a scoped sweep only after recording its queries, inclusion criteria, deduplication and selected-source results. Two zero-candidate passes can close that declared frontier for a dated snapshot; they cannot establish universal internet exhaustion. Nonzero rounds reopen the frontier and add a source-backed disposition or an explicit unresolved lead.

Before a work package starts, its owner follows its linked research to the actual pinned upstream API and rechecks changed versions, terms and assumptions. A missing fixture, unavailable source or unresolved hard contract becomes a tracked blocker. It is not silently improvised or labeled complete. A newly found candidate changes the relevant decision/test where useful; adding names alone does not raise implementation quality.

The current deliverable is a researched build specification with explicit unqualified boundaries. Stronger comparative claims require independent observed evidence against the named alternative. Private reference material is not a public source and is not reproduced.
