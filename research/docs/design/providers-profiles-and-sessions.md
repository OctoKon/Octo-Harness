# Providers, profiles, live switching and sessions

**Status: proposed, unimplemented; provider, session and production qualification n=0.** This incorporates the current user ruling: **local and cloud inference**, multiple providers/profiles, live model choice, resume/fork, a barebones default and user-created modules. It supersedes the earlier product-wide local-only ruling; a deliberately local-only profile remains strict. Start from [Pi source contracts](../foundations/pi-source-contracts.md), [model choice](user-controlled-models.md), [module installation](modular-installation.md) and [the master plan](../../../MASTER-PLAN.md). These are Splyce contracts unless an upstream source is explicitly identified.

The application, workspace operations, authoritative store, session records and optional memory/index storage remain local. A user-selected cloud model receives the explicitly permitted request content. This does not enable hosted agent execution or hosted memory storage. No provider/adapter is installed, logged into, enabled or selected merely because credentials exist in the environment. Setup can finish with no configured model; requests stay unavailable until the user selects a compatible binding.

## Identity and configuration ownership

| Proposed entity / owner   | Minimum contract                                                                                                                                                                                                             | Persistence and scope                                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider connection / C4  | Stable provider ID; wire protocol/API version; local or hosted endpoint identity; credential reference; account/project/region when applicable; adapter revision; observed capabilities and limits.                          | Local versioned configuration; secrets remain in credential facilities/environment, never profile exports or ordinary receipts. Same model name on two providers remains two identities.                        |
| Model binding / C4        | Provider ID plus actual model/deployment/checkpoint revision, tokenizer/template and quantization where applicable; operation, modality, tool/schema/thinking limits, context/output constraints and usage/cancel semantics. | Immutable binding revision. Discovery metadata is not authorization or proof of actual loaded identity. Unpinned hosted aliases are labeled mutable and trigger requalification.                                |
| Profile / C4, C2          | Named, versioned set of operation bindings, installed-module selections, user preferences, resource/budget limits and per-role data-class/endpoint egress policy.                                                            | Splyce-owned bundle over qualified Pi settings, not a claim of a Pi profile API. Local/user/workspace defaults are explicit; a session references a snapshot. Secrets/grants are not copied as ordinary fields. |
| Active selection / C1, C4 | Session/branch, profile and binding revisions, requested versus effective selection, readiness and next-turn/switch disposition.                                                                                             | Per-session; switching one session does not change another session or the saved workspace default unless separately requested.                                                                                  |
| Session / Pi plus C1      | Pi session identity and actual entry ancestry; Splyce run/branch anchors, workspace snapshot and profile/binding-change references.                                                                                          | Pi owns conversation/branch persistence; Splyce owns policy/effect evidence and reconciliation. No second conversation store becomes authoritative.                                                             |

Independent generation, extraction/summary, embed, rerank and optional typed decision/forecast/vision/audio/draft bindings can use different providers. One provider may serve several roles only when each operation qualifies. Profiles can be all-local, hosted-generation with local memory processing, or another explicit mixed selection. Choosing a cloud generator does not grant cloud embeddings or permission to upload retrieved private artifacts automatically. Every dispatched request checks current scope/data policy and records actual provider, binding, role and supplied evidence references. Stored state can be local while approved request content is processed remotely; never describe this as zero egress.

Profile changes cannot grant tool authority, remove policy/receipt validation or install modules silently. A profile referring to absent modules produces an explicit installation plan; acceptance of that plan is separate from selection. Imported settings cannot execute credential commands or install code. Optional cloud adapters/SDK dependencies follow the same selected-package closure as local runtimes; statically bundled upstream dependencies must be measured and pruned or disclosed as a failed barebones gate.

## User workflows and decisive tests

| User action                                | Required behavior                                                                                                                                                                                                                                           | Proposed case / owner                              |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Add two providers using the same model ID  | Distinct namespaces/endpoints/credential references; test only the chosen connection with declared probe data, timeout and cost visibility.                                                                                                                 | `C4_provider_identity` / C4                        |
| Add a custom API endpoint                  | User declares protocol and endpoint; validate the actual operation rather than guessing from its URL. Unknown wire protocol reports the missing adapter; a user can install/build a compatible plugin.                                                      | `C4_custom_protocol` / C4, I1                      |
| Create/copy/edit/delete a profile          | Versioned updates; copying omits secrets/grants, deletion reports referencing sessions/jobs and never deletes their history or silently changes bindings.                                                                                                   | `C4_profile_crud` / C4, J0                         |
| Switch model while idle                    | Commit and acknowledge requested selection immediately; validate identity/credentials/limits and show effective readiness. Warm compatible services avoid a host restart; cold weights/loading/network readiness can take time.                             | `C4_switch_idle` / C1, C4                          |
| Switch during a streamed/tool-bearing turn | Choose next-turn switch or explicit cancel-and-switch. Fence new dispatch, record the original turn's partial/canceled/uncertain state, settle owned tools, then activate the replacement. No mixed-provider turn or relabeling of earlier output.          | `C4_switch_stream` / C1–C4                         |
| Switch profile with different egress       | Revalidate every affected role and queued job under current policy. Prior local content is not uploaded until its scope/data-class grant permits the selected endpoint.                                                                                     | `C4_profile_egress` / C2, C4                       |
| Old model/service is down                  | Selected role reports unavailable. No implicit new provider, model, cloud route or billable retry; an optional user-configured fallback list is separately validated and visible.                                                                           | `C4_no_silent_fallback` / C4                       |
| Resume a session                           | Restore actual Pi ancestry, selected binding/profile references and workspace identity; reconcile effects first, then current grants/config. Missing package/model/credential is explicit; never replay uncertain tools or silently choose today's default. | `C1_resume_profile` / C1, C3, C4                   |
| Resume after files changed outside Pi      | Compare current workspace/snapshot with stored identity, invalidate stale verification/context, show conflict/rebase choices; history is not proof that old edits still exist.                                                                              | `C1_resume_workspace` / C1, C5                     |
| Fork at a selected point                   | Use actual Pi fork/tree semantics and Splyce branch anchors. Child sees only selected ancestry, no later sibling/future entries; append parent/fork metadata without mutating the source. Revalidate current authority.                                     | `C1_fork_point` / C1, C2                           |
| Fork to try another model/profile          | Child gets an explicit binding snapshot/change; parent remains unchanged. New fork does not copy credentials, acquire wider scope or replay effects.                                                                                                        | `C1_fork_model` / C1, C4                           |
| Fork into another workspace/worktree       | A conversation fork alone does not clone files or isolate processes. Explicit workspace creation/binding gets a new snapshot/grant; old verification does not certify it.                                                                                   | `C1_fork_workspace` / C1, C2, C5                   |
| Open two clients on one session            | One authoritative writer/lease with version fencing; other client attaches read-only or requests explicit controlled handoff. No concurrent double-send/effect or last-writer transcript loss.                                                              | `C1_writer_fence` / C1, J0                         |
| Disconnect/reconnect a client              | Recover from durable event cursor with ordering/deduplication; client closure does not imply canceled agent or stopped tools. Reconnection exposes actual run state.                                                                                        | `C1_reconnect_cursor` / C1, C3                     |
| Interrupt, crash or hard kill              | Durable intent without confirmed outcome remains uncertain; next launch reconciles physical state before any retry. Missing provider usage remains unknown, including after a charged cloud request.                                                        | `C3_session_crash` / C3                            |
| Compact or exceed the new model's context  | Preserve original ancestry/provenance; fit only through declared truncation/compaction policy and current model/data grant. Lossy summaries cannot certify effects; unsupported context is explicit.                                                        | `C1_context_transition` / C1, C4                   |
| Rename/list/search/archive                 | Scope-filter metadata before display/search; archive changes visibility, not authority, data deletion or job cancellation. Base listing needs no RAG/index module.                                                                                          | `C1_session_catalog` / C1, C2                      |
| Export/import/delete                       | Export excludes secrets and validates included data; import validates versions/paths/references before serving and never executes config. Deletion inventories Pi forks/compaction, local caches and optional modules.                                      | `R1_session_portability` / C1, M2 if installed, R1 |

The exact timing target for selection acknowledgement is registered and measured on each advertised client; there is no invented universal millisecond promise. Distinguish **request accepted**, **binding effective**, **model ready**, and **first output**. Do not preload every model to make a switching demonstration appear instant. User-requested prewarming is optional and reports resident/resource cost. API changes that cannot preserve required history/tool semantics fail visibly instead of silently dropping content.

## Provider protocol and effect boundaries

The [API-family matrix](../capabilities/provider-api-conformance.md) separates Chat Completions, Responses, Anthropic, Gemini, Bedrock, Vertex/Azure and native/embedding/rerank operations. Reuse Pi's actual adapters/serialization/session conversion when qualified; a gateway or compatibility label does not establish feature parity. Preserve provider-specific opaque reasoning/signature blocks only through their valid protocol; do not fabricate them or expose hidden reasoning as a portability requirement. Cross-provider history conversion must be source-audited and round-trip/failure tested. Pending calls need original tool IDs, complete validated arguments and exactly correlated results; partial JSON is never executable.

Classify failures: config/credential, policy denial, unsupported operation/model, context overflow, invalid output/schema, rate limit/quota, transport timeout, stream interruption, upstream server error, local load/resource failure and cancellation. Preserve request IDs, observed usage and redacted diagnostics. Honor supported retry hints with bounded user budgets; retry only before visible output/effects or under a proven safe continuation contract. Changing providers cannot erase a charged request or an uncertain effect. SDK helpers must not start a separate tool runner that bypasses Pi/Splyce admission.

Local-only profiles require zero inference egress, including auth/discovery/catalog/usage/embedding/extraction fallback. Hosted profiles allow only configured role/endpoint/data-class requests; changes to proxy/redirect/TLS/credentials/model identity trigger revalidation. Each SDK transport must qualify its actual request boundary; one global `fetch` wrapper is not proof for every SDK. Telemetry, analytics and automatic update checks remain off. User-initiated provider calls carry that provider's terms, processing/retention limits and costs; local deletion cannot claim removal of copies outside the application's control. Remote artifact/file uploads, server-side tools or persistent conversations require their own explicit supported capability and lifecycle record; do not enable them because an API offers them.

## Package and release mapping

C1 owns session/writer/fork/cursor contracts; C2 owns current data/tool authority; C3 owns durable transition and uncertain-effect recovery; C4 owns connections, versioned profiles/bindings and model changes; C5 owns workspace verification; I1 owns selected adapter acquisition; M1/M2 apply only when memory is installed; R1 proves actual installed client/platform/provider cells. Proposed core files remain `packages/splyce-pi/src/{index,policy,store,receipts,providers,verification,modules}.ts`, with optional implementations in selected modules. Do not introduce another agent loop, session manager or generic profile language.

Before claiming an API/provider cell supported, run deterministic protocol/fault fixtures and an opt-in real request for that exact adapter/model/operation/client combination. Freeze corpus, prompt/schema/tool fixtures, provider/API/model revisions and budgets; record receipts, raw sanitized protocol artifacts, commands, independent sample counts and limits. A real coding task must complete a permitted tool round-trip and final-snapshot verification, resume, fork and model switch. One successful text response does not establish production readiness, every model, all API variants or cloud privacy guarantees.
