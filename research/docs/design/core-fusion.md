# Pi-derived core fusion contract

**Architecture decision, reconciled 2026-10-26; implementation evidence n=0.** Splyce is a Windows desktop GUI over a **Splyce-owned Pi-derived engine**, not an unchanged Pi instance surrounded by independent agents. The user authorizes substantive edits inside Pi's model, tool, session, provider and lifecycle implementation. Preserve one existing model loop; do not rewrite Pi in Rust or add a competing conversation engine. [Stack](../foundations/desktop-stack-decision.md), [master plan](../../../MASTER-PLAN.md) and [80 assigned tasks](team-delivery-plan.md) control delivery.

Core fusion and selective installation address different concerns. Policy, current configuration, provider/model identity, receipt ordering, session ancestry, verification and module admission belong on the native engine path. Optional memory/RAG/LSP/editor/device/model implementations remain absent from the base artifact until selected. A native interface is not a reason to bundle every implementation, model or daemon. MCP remains interoperability for external tools; native product behavior need not masquerade as an external MCP service.

## Store and compatibility decision

J0 selects the actual durable store before C1/C2 admission. Conversation ancestry remains Pi-derived; operational decisions/effects/configuration have the ownership defined in [record contracts](implementation-contracts.md). If an initial build retains Pi's separate session log, no cross-store atomicity is claimed: explicit correlation and uncertain joins are mandatory. A later unified storage change must preserve/import/export the real Pi entry model and pass migration/rollback tests before replacing that log. It is not a second shadow transcript or a silent scope expansion. TD-01/03/09/15 record the chosen implementation before dependent tasks merge.

Every patch binds upstream symbol/revision, final fork commit, reason, source-ledger claim, affected work package, physical negative test and upgrade rehearsal. Preserve donor licenses and source-access obligations. Upgrade in a username branch, replay/rebase the patch inventory, rerun affected core and packaged GUI tests, and retain a compatible rollback path. Do not adopt upstream changes based on a version label alone.

**First integrated proof:** one packaged Windows GUI uses this engine/store to configure a permitted provider, edit a synthetic repository, deny an out-of-scope effect, interrupt, resume/fork, switch model and verify the final dirty-aware snapshot. Deliberately removing the native gate or durable commit must fail the proof. Component tests and research notes cannot substitute for that single wired path. No runtime code or proof is present yet.
