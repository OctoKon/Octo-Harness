Coding Agent, Harness, and Scaffold Research

Multi-Round Architectural Analysis, Documentation Index, and the Splyce Unified Specification

This report delivers a three-part engineering reference and system specification covering the 2026 AI software engineering landscape:

  1. A modular docs/ directory structure and a compact master docs/INDEX.md mapping 65 coding agents.
  2. A four-round chained architectural analysis of every major meta-harness, CLI agent, IDE extension, interoperability protocol, and autonomous software engineering (SWE) research scaffold.
  3. An imported architectural proposal for OmniHarness (omni), a unified CLI and agent harness. This is not an implemented Splyce specification.

Critical Empirical Finding

Static scaffolding bloat acts as a heavy cost multiplier that increases inference spend by 3x to 5x without improving task resolution. Controlled 2026 evaluations ("HarnessTax") indicate that holding the base LLM fixed while swapping between heavyweight harnesses (Claude Code, sending 16,581 tokens on Turn 1) and minimalist harnesses (Pi at under 1,000 tokens) shifts pass rates by less than run-to-run variance.

The imported OmniHarness proposal claims to address this trade-off through a sub-900-token micro-kernel, Cordis plugin composition, progressive disclosure, sandboxing, and offline harness evolution. These claims are unqualified and do not override Splyce's current Pi-first master plan.

Part 2: Chained Deep-Research Rounds

Click to expand each research round detailing architectural teardowns.

The defining architectural advance of 2026 is the decoupling of the agent execution harness from the harnessing optimizer that composes those components.

1.1 Google Research's Harness²

Formalizes recursive agent harnessing in an open world without ground-truth labels. It exposes an 8-component editable workspace tree (c1 through c8). It operates on a contrastive Propose–Probe–Compose step. Parallel and sequential modes enforce a resource identity of R = 4k rollouts and P = 3k improver sessions.

1.2 DeepSeek Harness (dsh)

Built on the rule that "Everything is a plugin" via a dependency-injection kernel called Cordis. Lifecycle managed via spatial composability (stable context keys) and temporal composability (reversible side-effects via ctx.effect()). Strict invariant: "Model-visible means logged."

1.3 Nous Research's Hermes Agent & LangChain's DeepAgents

Hermes centers on a closed skill-learning loop generating SKILL.md. DeepAgents features a 4-layer automatic context defense (delta-channel reducer, stale arg truncation, eviction disk spill, and 85% summarization).

2.1 Anthropic's Claude Code

Manages context through a three-layer compaction system (Microcompaction, Auto-Compaction, Manual) paired with a 6-step rehydration sequence. Utilizes AST BashTool parsing combined with macOS Seatbelt and bwrap sandboxing.

2.2 OpenAI Codex CLI

Introduces Pre-Main Process Hardening (ptrace block, zeroing RLIMIT_CORE), Default-on Kernel Sandboxing with .git write locks, and a 4-Pass Lenient Patch Applier (normalizing trailing whitespace and unicode).

2.3 OpenCode & Crush

OpenCode's signature is a built-in LSP diagnostic loop that feeds compiler errors back to the LLM observation block instantly. Crush utilizes Elm architecture for cell-based diff TUIs and shared multi-client workspaces.

2.4 Pi Coding Agent

Archetype of minimalism (<1,000 token prompt). Uses an Append-Only JSONL Session DAG for crash-recovery and seamless branching, plus a 4-Wire-Protocol translator that handles <thinking> handoffs across different LLM providers.

2.5 Aider

Pioneered the Personalized PageRank Repository Map and 13 Model-Adaptive Edit Formats. Its RepoMap builds a multigraph, applies PageRank biased to chat files, and fits tokens via binary search.

3.1 Cline → Roo Code → Zoo Code

Introduces Boomerang Tasks (subagents that return only a result summary, preventing exploration tokens from poisoning the parent's context), apply_diff with Middle-Out Levenshtein Fuzzy Matching, and Shadow Git Checkpoints for instant non-destructive rollbacks.

3.2 AWS Kiro & Cursor

Kiro focuses on Executable Specs (requirements.md, design.md, tasks.md) driving event-based background hooks. Cursor utilizes Auto-review shell sandboxes and fast inline apply models.

3.3 ACP vs MCP Protocol

ACP (Agent Client Protocol): Outer layer connecting any IDE to any Coding Agent via JSON-RPC 2.0.
MCP (Model Context Protocol): Inner layer connecting the Agent to external tools/APIs.

4.1 SWE-agent vs. mini-SWE-agent

SWE-agent introduced a controlled Agent-Computer Interface (ACI) windowed viewer and lint-on-edit rollbacks. As models improved, mini-SWE-agent v2 shifted to a stateless 100-line bash-only loop replacing tools with triple backticks.

4.2 Advanced Scaffolds

  • Agentless: Deterministic 3-phase pipeline (Localize → Repair → Validate) using AST majority voting.
  • AutoCodeRover: Treats repos as ASTs, runs Spectrum-Based Fault Localization (SBFL).
  • Moatless (SWE-Search): Replaces linear retries with Monte Carlo Tree Search (MCTS) utilizing hindsight feedback.
  • SWE-AF: Compiles PRDs into dynamic Issue DAGs signed with Verifiable Credentials.

Synthesizing findings from Rounds 1–4, Splyce is designed around four engineering invariants: a sub-900-token micro-kernel, Cordis spatiotemporal plugin extensibility, deterministic AST/LSP verification, and contrastive Harness² self-evolution.

// Cordis Spatiotemporal Context Kernel
export class CordisContext {
  private services = new Map();
  private effects = new Map();
  private waterfalls = new Map[]>();

  public provide(key: string, service: T, ownerPluginId = "core"): Disposer {
    this.services.set(key, service);
    const dispose = () => { this.services.delete(key); };
    this.effect(dispose, ownerPluginId);
    return dispose;
  }

  public effect(disposer: Disposer, ownerPluginId = "core"): void {
    const list = this.effects.get(ownerPluginId) ?? [];
    list.push(disposer);
    this.effects.set(ownerPluginId, list);
  }

  public async emitWaterfall(event: string, payload: C, terminal: () => Promise): Promise {
    const chain = this.waterfalls.get(event) ?? [];
    let index = -1;
    const dispatch = async (i: number): Promise => {
      if (i <= index) throw new Error(`Waterfall next() called multiple times in ${event}`);
      index = i;
      const fn = chain[i];
      if (!fn) return terminal();
      return fn(payload, () => dispatch(i + 1));
    };
    return dispatch(0);
  }
}

Module 3: Harness² Recursive Self-Evolution Engine (Propose-Probe-Compose)

// packages/evolver/src/propose-probe-compose.ts
export class Harness2Evolver {
  private readonly LEAK_MARKERS = ["RUBRICS.json", "score.json", "PASS_TO_PASS"];

  public validateTreeFailClosed(tree: HarnessCandidateTree, alwaysOnTokenCap = 900): string[] {
    const errors: string[] = [];
    const c1Prompt = tree.componentFiles[".omni/harness/c1-system-prompt.md"] ?? "";
    const approxTokens = Math.ceil(c1Prompt.length / 4);

    if (approxTokens > alwaysOnTokenCap) {
      errors.push(`OVER_CAP: c1 is ~${approxTokens} tokens (max ${alwaysOnTokenCap}).`);
    }

    for (const [filePath, content] of Object.entries(tree.componentFiles)) {
      for (const marker of this.LEAK_MARKERS) {
        if (content.includes(marker)) errors.push(`LEAK_TRIPWIRE: Forbidden rubric marker found.`);
      }
    }
    return errors;
  }

  public async runProposeProbeCompose(params: any) {
    if (params.estimatedUsd <= 0 || params.estimatedUsd >= params.capUsd) {
      throw new Error(`SPEND_CAP_GUARD: Spend must be below --cap-usd.`);
    }

    let currentTree = params.baseTree;
    for (let step = 0; step < params.kBudget; step++) {
      // 1. PROPOSE
      const candidates = await params.proposeFn(currentTree, params.kBudget);
      // 2. PROBE
      const evidences = await Promise.all([currentTree, ...candidates].map(c => params.probeFn(c)));
      // 3. COMPOSE
      const { adopted, lesson } = await params.composeFn(evidences, [currentTree, ...candidates]);
      currentTree = adopted;
    }
    return { adoptedTree: currentTree };
  }
}
