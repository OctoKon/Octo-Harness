# Splyce agent rules

Applies repository-wide; current human instructions take precedence. These rules apply to **every task**, including research, planning, implementation, review and handoff.

- **Ponytail ultra always.** Read [.skills/ponytail/SKILL.md](.skills/ponytail/SKILL.md) once per context and apply ultra. Finish every requirement with the smallest complete change; never cut correctness, safety or requested scope. Load only the conditional skills routed by [.skills/README.md](.skills/README.md).
- **Start from the assigned contract.** Read [MASTER-PLAN.md](MASTER-PLAN.md), your task in the [nine-person plan](research/docs/design/team-delivery-plan.md), dependencies, linked research, allowed paths, fixture, expected failures and definition of done. Resolve missing contracts before coding. One task has one primary owner; coordinate shared schemas/files before editing.
- **Never work or commit on `main`.** Fetch `origin/main`; use `<actual-GitHub-username>/<short-scope>` (for example `lapsecoder/provider-streams`). Branch from the current base or the declared dependency branch. Do not impersonate another member. Preserve existing work; no force pushes, destructive cleanup or unrelated edits.
- **Keep changes bounded and connected.** Build the [Pi-derived fused core](research/docs/design/core-fusion.md) and reuse its existing loop/primitives; native core improvements are authorized, with upstream patch/regression records. No silent Rust port or competing loop. Wire real callers, configuration, persistence, cleanup and user entrypoints; no dead modules or swallowed failures.
- **Windows desktop GUI V1.** Follow the [locked stack](research/docs/foundations/desktop-stack-decision.md) and [desktop contract](research/docs/design/desktop-application.md): Tauri 2/Rust, Svelte 5/strict TypeScript/Vite 8, Pi-derived Node engine. No CLI/TUI user product in V1. GUI E2E uses the packaged Windows app; Monaco is a selected optional module.
- **Respect product contracts.** [Barebones installation](research/docs/design/modular-installation.md), [custom plugins](research/docs/design/plugin-authoring.md) and [providers/profiles/sessions](research/docs/design/providers-profiles-and-sessions.md) govern selective dependencies, local/cloud data policy, live switching and recovery. No implicit installs, telemetry, provider/model fallback or grant expansion. Trusted in-process plugins are not sandboxed.
- **Delegate deliberately.** Honor the user's concurrency limit, including child agents. Give each worker a bounded deliverable, ownership, dependencies, acceptance and explicit suitable model when supported; tell workers others are present. The parent owns integration, conflict resolution and real-path verification.
- **Diagnose failures.** Reproduce, narrow, inspect omitted errors, test a hypothesis, fix the shared cause and rerun the affected checks. Repeated identical failure requires investigation, not blind retries. Validate boundaries; never mock the system under test or conceal an uncertain effect.
- **E2E before any PR.** Run every applicable end-to-end suite through the actual installed/loaded entrypoint, plus format/lint/type/build/integration and required negative/recovery cases. Open **no PR, including draft**, with failed, missing or unrun applicable E2E tests. Implement a missing required suite first. Docs-only changes use the real documentation pipeline; runtime E2E is explicitly N/A only when runtime behavior is unaffected.
- **Bind tests to delivery.** Record exact commands, final candidate revision/content snapshot, observed results and artifact links. Rerun affected checks after edits or conflict resolution. A fake service proves contract faults, not actual provider/device/installed support. Never call n=0, skipped checks or projections passed.
- **Make concise, complete PRs.** Target `main` from the username branch. Use a conventional title and short bullet points: task IDs and user-visible change/why; integration/compatibility or migration; exact validation/results with evidence; material limits/risks and required reviewers. UI changes include visual evidence and keyboard/accessibility/error-state checks. No transcript dumps or generic AI ceremony.
- **Require domain review.** Request `@MdSiddiqx` for every UI/UX change and its testing; request `@Itachi-1824` for backend changes; mixed PRs need both. Authors cannot approve themselves: lead-authored work gets the other lead's independent review plus the owning lead's domain/test evidence. No bypass or self-approval; [CONTRIBUTING.md](CONTRIBUTING.md) explains GitHub's enforcement limits.
- **Respect repository controls.** Commits use `feat|fix|refactor|docs|test|chore|perf|ci: description`; squash only, current passing required checks and resolved reviews. Never weaken protection/checks for green CI. Do not merge without the required independent approval.
- **Protect private material.** No private repository content, internal paths, transcripts, secrets or unpublished findings in public artifacts. Credentials use environment/credential facilities. Validate trust boundaries, preserve third-party notices/licenses, and inspect the publication diff for private data.
- **Keep research auditable.** Use public primary sources, dated claims and pinned code where relevant. Preserve counterevidence and unresolved gaps. Research belongs under [research/](research/README.md) with working category indexes. Separate proposed, source-observed, local-tested, CI-verified and live-tested; never claim universal completeness or performance without evidence.
- **Keep context lean; hand over precisely.** Preserve task/dependencies, decisions, changed paths, tests, revision, unresolved blockers and next action. Retrieve only missing exact history after compaction. Update the task/qualification record; concise outcome first, then evidence and limits, ending with skipped checks and material risk.

Before publication: `npm run format:check`, `npm run lint:markdown`, `npm run check:docs`, `npm run test:docs`, all change-specific gates, and privacy review. These documentation commands do not replace runtime E2E.
